# Interactive Video Editor Step Layout Design

## 背景

当前互动影游编辑页把作品标题、题材标签、云端项目包、内购配置、测试、发布和下载入口集中平铺在同一个长页面中。老用户可以直接找到按钮，但新用户较难理解从“编辑完成”到“发布交付”的顺序，也不容易判断当前作品还缺哪些发布前准备。

本设计将页面改为“上方信息展示区 + 下方弱引导步骤内容”的发布工作台。顶部保留全部主要操作，满足快速操作；下方用步骤结构解释先后顺序和当前状态，帮助新手按流程完成。

## 目标

- 让新手一眼知道互动影游发布前应依次处理题材、内购、测试、发布交付。
- 保留老用户的快速操作能力，顶部信息展示区继续放置保存、测试、发布或下架、下载 ZIP 等主要按钮。
- 将内购配置设为必经确认步骤，即使选择免费模式也需要明确保存或确认。
- 保持弱引导：步骤可自由切换，不做强制线性锁定；真正不可执行的动作继续由现有业务条件禁用。
- 第一版优先做前端布局与状态表达，不新增后端接口、数据库字段或测试记录持久化。

## 非目标

- 不重做 002 工具导入包生成逻辑。
- 不改变发布、下架、下载、保存题材、保存内购配置的业务语义。
- 不新增“最近一次测试时间”等需要后端持久化的数据。
- 不改现有中文文案含义，除非实现时为了步骤结构必须新增少量界面标题或提示。

## 页面结构

### 1. 顶部信息展示区

顶部信息展示区位于页面标题区，替代当前分散的 header action 和云端项目包卡片。它是作品总览和操作中枢，始终出现在步骤内容上方。

展示内容：

- 作品类型标识：互动影游编辑。
- 作品标题与编辑按钮。
- 发布状态：草稿、已发布。
- 保存状态：已保存、有未保存题材修改、保存中。
- 作品 ID、版本、题材数量。
- 关键提醒：例如题材未保存、题材数量不足、内购配置未保存。

保留全部主要操作：

- 保存题材或保存当前未保存配置。
- 进入测试。
- 发布作品或下架作品。
- 下载 002 可导入 ZIP。
- 返回创作中心、刷新可以继续放在信息区上沿或页面工具条，保持低优先级。

按钮层级：

- 主要动作：发布作品或下架作品、下载 ZIP。
- 次要动作：保存、进入测试、刷新、返回。
- 被禁用动作需要保留原因提示，避免用户只看到灰色按钮却不知道下一步。

### 2. 下方步骤内容区

信息区下方使用步骤式内容区。步骤导航可以是横向步骤条或分段标签，桌面端优先横向，移动端可折叠为横向滚动标签。

步骤为：

1. 题材标签
2. 内购配置
3. 测试作品
4. 发布交付

步骤切换规则：

- 用户可以自由切换任一步。
- 每一步显示状态：已完成、未完成、未保存、建议处理。
- 下一步不因上一部未完成而被隐藏或锁定。
- 发布动作仍按现有业务条件禁用；步骤区负责解释禁用原因。

## 步骤设计

### 步骤一：题材标签

承载当前“选择 1-2 个题材标签”的内容。

状态规则：

- 未完成：选择数量少于最低要求。
- 未保存：选择数量合法但存在未保存修改。
- 已完成：选择数量合法且已保存。
- 错误：题材加载或保存失败时，在本步骤内显示错误和重试入口。

交互：

- 保留标签 chip 选择方式。
- 保留保存题材按钮。
- 显示当前选择名称和数量。
- 选择超过上限时保持现有限制或提示，不引入新的批量操作。

### 步骤二：内购配置

承载当前“互动影游内购配置”的内容，作为必经确认步骤。

信息结构：

- 顶部显示成本与收益区，用于理解商业化结果。
- 中部显示付费模式选择：免费、买断、脚本或节点付费等现有模式。
- 下方显示对应价格和目录配置。
- 底部保留保存内购设置按钮。

状态规则：

- 未完成：内购配置未加载成功，或当前配置存在无法保存的输入。
- 未保存：草稿配置与已保存配置不同。
- 已完成：配置已保存；免费模式也视为已完成。
- 锁定：已有付费购买导致模式不可切换时，展示锁定原因，仍允许查看统计和可编辑项。

交互：

- 不把内购配置隐藏成高级设置，因为用户已确认它是必经步骤。
- 复杂配置保持在该步骤内部，不挤压顶部信息展示区。
- 保存中禁用相关输入和保存按钮，并提供明确保存中状态。

### 步骤三：测试作品

提供进入测试的明确入口，帮助新手理解发布前应先体验作品。

第一版不新增测试记录持久化。测试步骤作为软引导：

- 提供“进入测试”主按钮。
- 展示测试前建议：先保存题材和内购配置，再进入测试。
- 如果存在未保存题材或内购配置，展示提示，但不阻止用户进入测试，除非现有业务逻辑已经阻止。
- 进入测试使用当前已有路由，不新增接口。

状态规则：

- 建议处理：存在未保存配置。
- 可测试：当前作品可进入测试。
- 无法测试：作品 ID 缺失、加载失败或现有测试路由不可用。

### 步骤四：发布交付

聚合发布、下架、下载 002 ZIP 和当前包信息。

展示内容：

- 发布状态：草稿或已发布。
- 发布前检查：题材、内购配置、保存状态。
- 发布或下架按钮。
- 下载 002 可导入 ZIP 按钮。
- 作品 ID、版本、包说明可以在此步骤中再次展示，但顶部信息区仍保留精简总览。

状态规则：

- 未准备好：题材不足、题材未保存或内购配置存在错误。
- 可发布：满足现有发布按钮条件。
- 已发布：显示下架入口和下载入口。
- 下载中：禁用下载按钮并显示准备 ZIP 的状态。

交互：

- 发布按钮在顶部和发布交付步骤中都可以出现，但禁用条件必须一致。
- 如果按钮禁用，发布交付步骤显示具体原因。
- 下载 ZIP 不依赖是否发布，除非现有业务逻辑已有约束。

## 状态与数据流

页面继续使用现有 `InteractiveVideoEdit` 数据加载、保存题材、保存内购、发布、下架、下载和测试跳转逻辑。

新增的前端派生状态可以从已有数据计算：

- `themeStepStatus`：由已选题材数量、`hasUnsavedThemeTags`、保存中和错误状态计算。
- `monetizationStepStatus`：由内购数据是否加载、草稿是否可保存、保存中和保存错误计算。
- `testStepStatus`：由作品是否加载成功、是否存在未保存配置计算。
- `deliveryStepStatus`：由发布状态、题材状态、内购状态、下载中和发布中状态计算。

这些状态只服务 UI 展示和按钮说明，不改变后端数据结构。

## 组件拆分建议

实现时可在当前页面内先做局部拆分，避免一次性重构过大。

建议组件：

- `EditorOverviewPanel`：顶部信息展示区。
- `EditorStepTabs`：步骤导航和步骤状态。
- `ThemeTagsStep`：题材标签步骤。
- `MonetizationStep`：内购配置步骤，复用现有渲染逻辑。
- `TestStep`：测试入口和软提示。
- `DeliveryStep`：发布交付入口和检查提示。

如果第一版为了降低风险，也可以先把这些组件作为同文件内的小渲染函数，待布局稳定后再拆文件。

## 响应式设计

桌面端：

- 顶部信息展示区采用左右结构：左侧作品信息，右侧操作按钮。
- 作品元信息使用紧凑网格展示。
- 步骤导航横向展示，步骤内容占满页面主体宽度。

移动端：

- 顶部信息展示区纵向排列，标题、状态、元信息、按钮分组依次展示。
- 操作按钮可以换行，但每个按钮保持清晰点击面积。
- 步骤导航横向滚动或两列分段，不出现横向页面滚动。
- 内购配置保持单列，避免卡片套卡片。

## 错误与边界状态

- 页面加载失败时继续显示现有错误状态，不进入步骤内容。
- 题材加载为空时，题材步骤显示空状态和后台配置提示。
- 内购配置加载失败时，内购步骤显示错误，不影响题材、测试和发布交付步骤查看。
- 保存中、发布中、下架中、下载中必须禁用对应重复提交按钮。
- 有未保存题材时，发布按钮继续按现有逻辑禁用，并在发布交付步骤显示原因。
- 已有付费购买导致付费模式锁定时，在内购步骤说明锁定原因。

## 验证计划

实现后需要至少完成：

- 前端构建或类型检查，确认页面拆分和样式没有破坏编译。
- 针对步骤状态派生逻辑做轻量验证，覆盖题材未选、题材未保存、已保存、已发布、下载中等状态。
- 在桌面宽度和移动宽度检查布局，确认顶部按钮不重叠、步骤导航可用、内购配置不产生横向滚动。
- 最终执行 `git status --short --untracked-files=all`，确认没有临时验证产物残留。

## 第一版验收标准

- 打开互动影游编辑页时，用户先看到统一的信息展示区，而不是分散卡片。
- 用户无需滚动即可看到作品状态和全部主要操作按钮。
- 下方内容通过 4 个步骤组织，能自由切换。
- 题材、内购、测试、发布交付各自有明确状态。
- 发布不可用时，用户能在发布交付步骤看到具体原因。
- 内购配置作为必经步骤展示，免费模式也能被清晰确认。
- 不新增 API，不新增数据库字段，不改变现有发布、下架、下载、保存逻辑。
