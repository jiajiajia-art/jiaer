## 三、推荐方案：小说 = 独立 `games` 行 + R2 正文

不把小说塞进回放 `meta.json`，而是新建一条 **`games` 记录**，与回放、原作三方隔离。

```
用户创建回放（默认勾选「创建成小说」）
        │
        ▼
POST /api/visual/replay/create-from-session
        │
        ├─► 写 Replay R2（现有逻辑）
        ├─► 新建 games 行（engine=NOVEL, is_public=0）
        └─► 编译 replay steps → novel content R2

数据关系：
  novel.source_file_id    → 原作
  novel.source_replay_id  → 回放
  novel.creator_user_id   → 回放创建者（小说管理者）
```

### 为何选这条路径

- 上架/下架、封面、统计可复用现有 `games` + `GameStatsView` / `PublishSettingsModal`
- `file_id` 独立，不会污染原作编辑器数据
- 详情页用 `engine === 'NOVEL'` 做条件分支，不影响其他类型

## 四、数据模型设计

### 4.1 D1 `games` 表扩展（Migration）

```sql
-- 建议新增列（实现时可微调命名）
ALTER TABLE games ADD COLUMN source_file_id TEXT;
ALTER TABLE games ADD COLUMN source_replay_id TEXT;
ALTER TABLE games ADD COLUMN source_author_name TEXT;
ALTER TABLE games ADD COLUMN source_author_user_id TEXT;
ALTER TABLE games ADD COLUMN novel_content_version TEXT DEFAULT '1';
```

**小说作品字段约定**：

| 字段 | 取值 |
|------|------|
| `engine` | `NOVEL` |
| `game_tags` | `NOVEL`（与现有 TXT/AVG 标记方式一致） |
| `creator_user_id` | 创建回放的用户（小说管理者） |
| `title` | 默认 = 回放标题 |
| `description` | 默认 = 回放简介 |
| `cover_url` | 默认 = **原作** `cover_url`（创建时复制，后续可独立替换） |
| `author_name` | 默认 = **原作** `author_name`（展示用快照） |
| `is_public` | 默认 `0`（草稿） |
| `files` | `public/visual/novels/{novelFileId}/` |

### 4.2 R2 小说正文

```
public/visual/novels/{novelFileId}/
  content.json      # 章节/段落结构化正文
  meta.json         # 可选：字数、章节数、编译版本
```

**`content.json` 建议结构**：

```typescript
{
  novelFileId: string;
  sourceFileId: string;
  sourceReplayId: string;
  compiledAt: number;
  chapters: Array<{
    id: string;
    title?: string;
    paragraphs: Array<{
      type: 'narration' | 'dialogue' | 'scene';
      speaker?: string;
      text: string;
      sceneImage?: string;
    }>;
  }>;
}
```

**编译来源**：优先用刚写入的 replay steps（`readAllReplayStepsForCompatibility`），不依赖可能过期的 session。

### 4.3 数据隔离边界

| 数据 | 隔离策略 |
|------|----------|
| 小说 `file_id`、封面、标题、上架状态 | 独立维护 |
| 原作 `world/npc/scene` | **只读引用**；小说创建者不拥有编辑权 |
| 回放 R2 | 独立；小说通过 `source_replay_id` 关联 |
| 小说正文 | 创建时一次性编译快照；原作后续改动不自动同步 |

## 五、API 设计

### 5.1 扩展创建回放（P0 核心）

**`POST /api/visual/replay/create-from-session`**

请求新增字段：

```typescript
{
  // 现有字段：sessionId, fileId, title, description?, visibility, range?
  createAsNovel?: boolean;  // 默认 true（与产品图一致）
}
```

响应扩展：

```typescript
{
  success: true;
  replayId: string;
  novelFileId?: string;  // createAsNovel=true 时返回
}
```

**服务端流程（同一事务语义；失败则整体回滚或补偿删除）**：

1. 校验 session 归属 + 原作存在
2. 创建 replay（现有逻辑）
3. 若 `createAsNovel !== false`：
   - `novelFileId = hexId()`
   - 读原作 `games` 行 → 复制 cover / author_name / source_author_*
   - 编译 replay steps → `content.json`
   - `INSERT games`（`engine=NOVEL`, `is_public=0`）
   - 可选：写 R2 index `public/visual/novels/index/{novelFileId}.json`

### 5.2 小说专用 API（P0）

| 方法 | 路由 | 用途 |
|------|------|------|
| `GET` | `/api/visual/novel/:novelFileId/meta` | 详情页：含原作者、来源作信息 |
| `GET` | `/api/visual/novel/:novelFileId/content` | 阅读页拉正文（可分章分页） |
| `PATCH` | `/api/auth/novel/:novelFileId/cover` | 创作者换封面（或复用现有上传能力） |
| `GET` | `/api/auth/games/user?workType=novel` | 小说管理列表（或在现有 user games 上加筛选） |

### 5.3 发布 / 下架

复用现有 publish / unpublish，增加守卫：

- `engine === 'NOVEL'` 时跳过「世界观/角色/场景完整性」校验
- 校验：`content.json` 存在且非空、`title` / `cover_url` 有效
- 路由层禁止把小说误发布成 Galgame 游玩入口

## 十、风险与对策

| 风险 | 对策 |
|------|------|
| 创建回放成功但小说失败 | API 层同事务/补偿删除 replay；或返回 partial 状态供重试 |
| 重复创建多本小说 | 同一 `replayId` 唯一约束或创建前检查 |
| 发布校验误拦 NOVEL | `gamesPublish.js` 显式分支跳过 Visual 四步校验 |
| 激励计划误计入小说 | `engine=NOVEL` 排除 incentive 计算 |
| 与「TXT→世界观」改名冲突 | 互不影响：世界观是 TXT 展示名，小说是新 `engine` |

---

## 十一、与「TXT 改世界观」需求的关系

| 需求 | 关系 |
|------|------|
| TXT → 世界观（展示层重命名） | 改 TXT 引擎作品的**形态角标**文案 |
| 回放创建小说 | 新增 `engine=NOVEL` 的**独立作品类型**，角标为「小说」 |

两者可并行开发，无数据层冲突。

---

## 十二、结论

该需求是**新作品类型（NOVEL）+ 回放创建时联动生成**，不是修改现有回放或普通详情逻辑。

技术路径：**扩展 `create-from-session` 原子写 replay + novel games 行 + R2 正文**；前端用 `engine === 'NOVEL'` 在三处差异化（弹窗、草稿管理、详情页）。

待 Phase 0 产品确认后进入实现。
