# Funloom 平台功能文档

## 1. 文档说明

这份文档基于当前客户端代码整理，目标是帮助 UI 外包快速理解 `funloom` 平台已经具备的功能模块、页面层级和主要交互关系。

文档尽量从“用户能看到什么、能做什么”的角度描述，不展开技术实现。

说明规则：

- `已存在`：前端代码里已经有明确页面或功能入口。
- `预留/弱化`：代码里有入口或占位，但当前不是完整主流程，设计时可以作为次级模块处理。
- `开发中`：代码里明确写了占位或未完成提示，不建议当作当前主功能。

---

## 2. 平台定位

Funloom 是一个围绕“互动故事内容消费 + AI 辅助创作 + 作品运营管理”构建的平台，核心有三类能力：

1. 用户浏览和体验互动作品。
2. 创作者上传设定、生成内容、编辑并发布作品。
3. 平台侧进行公告发布、运营数据查看和后台管理。

从产品结构看，平台不是单一阅读器，而是一个同时包含：

- 内容首页
- 作品详情页
- 游戏体验页
- 创作者工作台
- 编辑器
- 用户中心
- 运营后台

的完整内容平台。

## 3. 角色与使用对象

### 3.1 普通用户

主要行为：

- 浏览首页内容
- 查看作品详情
- 开始体验作品
- 点赞、分享
- 签到、积分获取
- 查看自己的积分和邀请码

### 3.2 创作者

主要行为：

- 进入创作中心
- 新建作品
- 上传设定文档或一句话生成
- 编辑世界观、角色、场景、地图等内容
- 测试体验作品
- 发布、下架、删除作品
- 查看自己作品的数据表现和收益

### 3.3 管理员 / 运营

主要行为：

- 发布和维护首页公告
- 查看平台整体数据报表
- 进入后台管理页

平台有统一导航体系：

- 移动底部导航

### 5.1.3 弹窗型运营触达

`已存在`

首页存在多类运营弹窗：

- 首页公告弹窗
- 签到弹窗
- 加群弹窗

这说明平台有比较明显的“内容分发 + 用户运营”双目标。

## 5.2 首页

对应页面：`/home`

### 5.2.1 首页轮播 Banner

`已存在`

首页顶部有主轮播区域，支持：

- 自动轮播
- 手动切换
- 移动端手势滑动
- 点击进入作品详情

适合 UI 重点设计成平台核心内容曝光位。

### 5.2.2 全部作品瀑布/卡片流

`已存在`

首页主体是作品列表，支持：

- 卡片式展示
- 分页追加加载
- 下滑自动加载更多

这是平台最核心的内容消费入口。

### 5.2.3 首页公告

`已存在`

平台会拉取最新公告，并在合适时机弹出。

说明首页除了内容分发，还有平台通知、活动说明、版本说明等功能。

### 5.2.4 新用户运营触点

`已存在`

首页会根据用户状态触发：

- 首次登录引导加群
- 未签到用户的签到提醒

这部分适合在 UI 上做成不打扰但可感知的运营组件。

### 5.2.5 限时优惠 / 专题内容

`预留/弱化`

代码中存在“优惠作品列表”和专题页路由，但首页当前主界面以“全部作品”为主，优惠专区更像可扩展模块。

设计时可以保留“活动专区/限时优惠”的版位，但不必压成当前首页第一优先级。

## 5.5 作品详情页

对应页面：`/game/:fileId`

这是平台最关键的转化页面之一。

### 5.5.1 基础信息展示

`已存在`

详情页展示内容包括：

- 作品封面
- 标题
- 类型标签
- 评分
- 作者信息
- 作品简介

### 5.5.2 用户互动

`已存在`

当前详情页支持：

- 点赞
- 分享
- 复制链接

这是典型的内容传播入口。

### 5.5.3 开始体验前的模式选择

`已存在`

详情页不是直接进游戏，而是先做开始方式分流，当前支持：

- 新的开始
- 继续体验
- 读取存档

说明作品详情页同时承担“进入游戏前台”的作用。

### 5.5.4 多种作品类型分流

`已存在`

详情页会根据作品类型，把用户带去不同体验页：

- 文本互动作品
- 地图探索式互动作品
- 自定义互动作品

这意味着详情页 UI 需要允许不同作品类型呈现不同的开始提示和说明。

### 5.5.5 作品更新提醒

`已存在`

如果作品内容更新过，平台会在继续体验前提醒用户注意旧存档兼容问题。

这类提示适合做成轻量但明确的风险说明模块。

## 5.6 互动体验模块

平台当前有三种不同的体验形态。

### 5.6.1 文本互动作品体验

对应页面：`/galgame`

`已存在`

核心功能包括：

- 开场介绍
- 正常演出模式
- 纯文本模式
- 历史记录查看
- 自动播放
- 设置面板
- BGM 开关与音量控制
- 存档
- 读档
- 删除当前进度并重开
- 回放分享

如果从 UI 结构理解，这一页是“视觉小说/互动小说播放器”。

### 5.6.2 文字体验中的增强能力

`已存在`

在部分白名单作品里，还存在额外能力：

- 角色属性面板
- 服务端属性同步

这说明平台支持“轻养成”方向的作品。

### 5.6.3 地图探索式互动体验

对应页面：`/galgameMap`

`已存在`

这是另一套玩法页面，核心功能包括：

- 世界地图浏览
- 场景进入
- 子场景进入
- NPC 互动
- 功能型 NPC 互动
- 玩家属性查看
- 历史记录查看
- 回合推进
- 设置面板
- 音乐控制
- 删除当前进度并重开

如果给 UI 外包描述，可以把它理解为：

- “地图探索 + 节点触发 + 对话互动”的故事玩法页

### 5.6.4 自定义互动作品体验

对应页面：`/customif/:appId`

`已存在`

这类作品不是平台原生 UI，而是通过 iframe 方式承载自定义前端内容。

从产品上看，它表示平台支持：

- 第三方/定制化互动玩法接入
- 作品以独立页面形式运行
- 平台负责会话、宿主和外围能力

对 UI 设计来说，这一块更像“全屏容器页”。

3. 编辑角色
4. 编辑场景与 BGM

- 直接发布

- 错误信息弹窗

### 5.9.3 无文档直接创建

`已存在`

创作者可以不上传文档，直接创建空白作品，再手动填写内容。

### 5.9.4 一句话生成作品

`已存在，主要在文本互动模式`

## 6. 当前平台的核心产品链路

如果从实际使用链路理解，当前平台有 4 条主线。

### 6.1 用户消费链路

首页 -> 作品详情 -> 选择开始方式 -> 进入互动体验 -> 存档/继续/分享

### 6.2 创作者生产链路

创作中心 -> 选择创作类型 -> 上传文档或一句话生成 -> 编辑世界观/角色/场景/地图 -> 测试体验 -> 发布

### 6.3 创作者运营链路

创作中心 -> 查看已发布/草稿作品 -> 进入单作品管理页 -> 查看数据 -> 编辑 / 发布 / 下架 / 删除

### 6.4 平台运营链路

后台公告系统 -> 首页公告触达

以及：

数据分析页 -> 查看平台整体运营数据

## 7. 给 UI 外包的布局重点建议

这部分不是代码原话，而是基于现有功能结构给出的设计整理建议。

### 7.1 优先级最高的页面

建议重点投入设计资源的页面：

1. 首页
2. 作品详情页
3. 文本互动体验页
4. 地图互动体验页
5. 创作中心
6. 创作编辑器

因为这些页面是平台的核心使用频次区域。

### 7.2 适合做成统一设计体系的模块

建议抽成统一组件体系的内容：

- 作品卡片
- 顶部导航 / 底部导航
- 弹窗系统
- 详情页头图区
- 数据卡片
- 步骤导航
- 表单区块卡片
- 上传状态卡片
- 保存确认弹窗

### 7.3 编辑器建议按“步骤流”设计

编辑器不是普通后台表单，实际上是“分步创作流程”。

建议 UI 强化：

- 当前步骤
- 已完成步骤
- 下一步引导
- 未保存提醒
- 测试体验 / 发布这两个顶部主按钮

### 7.4 体验页要按两套玩法分开设计

不要把互动体验统一成一种页面。

当前至少有两套核心体验形态：

- 文本演出型
- 地图探索型

第三类自定义互动则更像容器页，不必套进统一阅读器逻辑。

### 7.5 明确区分“平台运营区”和“用户消费区”

平台里既有面向用户的内容界面，也有面向创作者和运营的后台界面。

建议 UI 上至少区分三种风格层级：

- 内容消费区
- 创作者工作台
- 管理后台

## 8. 建议在设计稿里标注的“非完整功能”

为了避免设计范围失控，以下内容建议在项目沟通时明确标记：

- 看广告得积分：开发中
- 后台积分修改：预留中
- 价格体系：有基础能力，但当前不是主流程
- 优惠专区：首页里不是当前主视觉重点
- 搜索框：当前代码里有 UI 位置，但不是明确完整功能闭环

---

## 9. 一句话总结

Funloom 当前不是单纯的“小说阅读页”，而是一个围绕互动作品展开的完整平台，已经具备：

- 内容分发
- 作品详情转化
- 两种核心互动玩法
- 创作者工作台
- AI 辅助编辑器
- 自定义互动上传
- 用户积分与账号体系
- 平台公告与运营分析

如果要做 UI 规划，最适合把它当作“互动内容平台 + 创作者工具平台”的双端产品来设计。
