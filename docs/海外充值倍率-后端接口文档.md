# 海外充值倍率 — 后端接口文档

## 1. 背景与规则

- 国内（微信 / 支付宝）按 **人民币** 收款，价格不变。
- 海外支付（EnjoyPayment）按 **真实美元（USD）** 收款。
- 海外价格由后台配置的 **倍率** 决定：

```
海外价（USD）= ceil(人民币价 × 倍率 × 100) / 100      // 向上取整到美分
```

  例：¥6 × 0.15 = $0.90；¥68 × 0.15 = 10.2 → $10.20；¥128 × 0.147 = 18.816 → $18.82。
- 倍率分两级：
  - **默认倍率** `defaultMultiplier`：必填，> 0。
  - **档位倍率** `multiplier`：可选，`null` 表示跟随默认倍率。
- **KK币到账数与币种无关**：海外买 60 KK币档位，到账仍是 60（首充 66）。
- 会员卡（周卡 / 月卡）海外价使用 **默认倍率**。
- 自定义金额（海外）：用户输入美元，到账 KK币 = `floor(美元 ÷ 默认倍率 × 10)`，最少 1；不参与首充加赠。
- **以后端计算结果为准**：前端只做展示，后端下单时必须用同一公式重新计算，不得信任前端传入的金额。

> 前端兜底：后端未下发倍率时前端按 0.15 展示，仅防止页面空白，后端上线后应始终下发。

## 2. 数据存储建议

表 `overseas_pricing_config`（单行）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 固定 1 |
| currency | varchar(8) | 固定 `USD` |
| default_multiplier | decimal(10,4) | 默认倍率 |
| updated_by | varchar | 操作管理员 userId |
| updated_at | datetime | |

表 `overseas_pricing_plan`：

| 字段 | 类型 | 说明 |
|---|---|---|
| plan_id | varchar PK | 如 `dr_6_v2`，与 KK币档位 id 一致 |
| multiplier | decimal(10,4) NULL | NULL = 跟随默认倍率 |
| updated_at | datetime | |

建议另记一张操作日志表（旧值 / 新值 / 操作人 / 时间），便于审计。

## 3. 管理后台接口

需管理员权限，非管理员返回 403。

### 3.1 获取配置

`GET /admin/pay/overseas-pricing`

```json
{
  "success": true,
  "message": "ok",
  "data": {
    "currency": "USD",
    "defaultMultiplier": 0.15,
    "plans": [
      { "planId": "dr_6_v2",   "label": "60 KK币",   "cnyPrice": 6,   "multiplier": null },
      { "planId": "dr_30_v2",  "label": "300 KK币",  "cnyPrice": 30,  "multiplier": 0.14 },
      { "planId": "dr_68_v2",  "label": "680 KK币",  "cnyPrice": 68,  "multiplier": null },
      { "planId": "dr_128_v2", "label": "1280 KK币", "cnyPrice": 128, "multiplier": null },
      { "planId": "dr_328_v2", "label": "3280 KK币", "cnyPrice": 328, "multiplier": null }
    ]
  }
}
```

- `plans` 返回当前所有上架的 KK币档位（顺序即前台展示顺序），未配置的档位 `multiplier` 为 `null`。

### 3.2 保存配置

`PUT /admin/pay/overseas-pricing`

```json
{
  "defaultMultiplier": 0.15,
  "plans": [
    { "planId": "dr_6_v2",  "label": "60 KK币",  "cnyPrice": 6,  "multiplier": null },
    { "planId": "dr_30_v2", "label": "300 KK币", "cnyPrice": 30, "multiplier": 0.14 }
  ]
}
```

- 只使用 `planId` 和 `multiplier`，`label` / `cnyPrice` 忽略（以服务端档位数据为准）。
- 校验：
  - `defaultMultiplier`：数字，`0 < x ≤ 10`，最多 4 位小数。
  - `multiplier`：`null` 或同上范围。
  - `planId` 必须是已存在档位，未知 id 返回 400。
  - 换算后海外价 < $0.50 时返回 400（EnjoyPayment 及卡组织通常有最低金额，按实际渠道调整）。
- 成功返回与 3.1 相同结构的最新配置。
- 错误示例：`{ "success": false, "code": "INVALID_MULTIPLIER", "message": "倍率需为大于 0 的数字", "data": null }`
- 保存后需让用户信息缓存失效（见第 4 节），使前台立刻生效。

## 4. 前台下发（用户信息接口）

在现有用户信息接口（`auth.getUserInfo` 返回的 `user`）中新增 / 扩展字段：

```json
{
  "overseasPricing": { "currency": "USD", "rate": 0.15 },
  "kkRechargePlans": [
    {
      "id": "dr_30_v2",
      "price": 30,
      "baseDiamonds": 300,
      "firstBonusDiamonds": 30,
      "firstTotalDiamonds": 330,
      "firstChargeEligible": true,
      "label": "300 KK币",
      "overseasMultiplier": 0.14
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `overseasPricing.rate` | 默认倍率 |
| `kkRechargePlans[].price` | 仍为 **人民币** 价，不要改成美元 |
| `kkRechargePlans[].overseasMultiplier` | 该档位生效倍率；跟随默认时可省略或返回默认值 |

## 5. 海外下单接口改造

`POST /pay/overseas/create`（请求体不变）

服务端计算：

| 订单类型 | 实收美元 |
|---|---|
| `diamonds` + `planId` | `ceil(档位人民币价 × 档位生效倍率 × 100) / 100` |
| `diamonds` + `amount`（自定义） | `amount` 即美元，校验 ≥ 最低金额且最多 2 位小数；到账 = `floor(amount ÷ 默认倍率 × 10)` |
| `subscription` | `ceil(会员人民币价 × 默认倍率 × 100) / 100` |

- 发给 EnjoyPayment 的币种为 `USD`，金额为上述美元金额（美分整数按渠道要求）。
- 订单表需新增并落库快照：`currency`、`amount_minor`（美分）、`multiplier`、`cny_reference_price`，避免之后改倍率影响历史订单和对账。
- 回调验签时校验回调金额与币种 = 订单快照，不一致则不发放。

响应在现有字段基础上新增：

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "outTradeNo": "...",
    "payUrl": "https://...",
    "mchOrderNo": "...",
    "currency": "USD",
    "amount": 4.20,
    "amountMinor": 420,
    "multiplier": 0.14,
    "notifyUrl": "...",
    "returnUrl": "...",
    "returnWebBase": "..."
  }
}
```

- `amountYuan` / `amountFen` 对海外订单已无意义，可保留为人民币参考价或在过渡期后移除；前端不依赖它们。

## 6. 上线顺序

1. 建表 + 写入默认倍率（建议 0.15，由财务按汇率和渠道费率确认）。
2. 上线 3.x 管理接口与第 4 节下发字段。
3. 上线第 5 节下单改造，并与前端展示价核对一遍所有档位。
4. 运营在后台「KK币管理 → 海外充值倍率」调整。
