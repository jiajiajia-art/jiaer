## 1. 已在完整文档写清的条目（摘要）

**1.1 评论排序**：`GET /auth/games/{fileId}/ratings` 新增 `sort`（默认 `latest` 按 `created_at` 倒序；`hot` 按 `like_count` 倒序，同分按时间）。只排根评论，先排序再分页。

**1.2 评分口径**：`rating_avg` 为五星制平均分，统一返回 number 或 null；`rating_count` 为有评分的根评论数；无人评分返回 `null` / `0`。前端展示 = 平均星数 × 2。

**1.3 AI 线路**：新增 `GET /api/romance/ai-routes?capability=text|image`；`play/complete`、`world-gen/complete`、`images/generate` 的 body 新增可选 `routeId`，不传走默认线路，扣费按线路倍率。请告知线路失效时是「回落默认」还是返回 409 `ROUTE_UNAVAILABLE`。

**1.4 对话改世界**：`POST /api/romance/play/complete` 支持 OpenAI 格式的 `tools` / `tool_choice`，返回 `tool_calls`。

**1.5 点赞**：`POST /auth/games-stats/like` 返回 `{ fileId, isLiked, likeCount }`（切换后的值）；同一用户并发请求不能重复计数。

**1.6 浏览记录**：前端暂存在浏览器本地（`localStorage` 键 `browsing_history_v1:<userId>`，最多 100 条）。需要：`POST /auth/games-stats/visit` 同时写浏览记录；新增 `GET /auth/games/history?limit=&offset=`（返回结构与收藏列表一致）和 `DELETE /auth/games/history`。上线后前端改读接口。另外：书架里本人视角的「已发布」已并入「我的作品」。

**1.7 签到弹窗**：不需要新接口；`week.days` 固定 7 条，`days[].totalPoints = basePoints + weeklyBonusPoints`，`makeupCardCount` 无卡返回 0。被隐藏的展示字段请保留。

## 2. 手机应用 `content` 改为 `kkapp@1` 配置（新增，完整文档未写）

**变化**：创作者创建 / 编辑手机应用时，`content` 不再是 `{ "text": "..." }`，而是一个可交互的应用配置对象。

涉及接口（已有）：

| 方法 | 路径 |
|------|------|
| POST | `/api/auth/platform-apps`（创建） |
| PUT | `/api/auth/platform-apps/{appId}`（修改） |
| GET | `/api/platform-apps`、`/api/platform-apps/batch`、`/api/platform-apps/{appId}`（读取） |

请求里的 `content` 示例：

```json
{
  "schema": "kkapp@1",
  "type": "browse",
  "theme": { "accent": "#ff6a3d", "dark": false },
  "home": "main",
  "pages": [
    {
      "id": "main",
      "title": "首页",
      "blocks": [
        { "kind": "header", "title": "星光兼职" },
        { "kind": "list", "title": "今日岗位", "items": [
          { "id": "job1", "title": "商场促销", "action": {
            "effects": [{ "metric": "money", "delta": 200 }],
            "cooldownDays": 1, "toast": "赚了 200 元"
          } }
        ] }
      ]
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| `schema` | `"kkapp@1"` | 固定值，用于版本识别 |
| `type` | `chat \| message \| browse \| read \| video \| job` | 与应用外层 `type` 一致 |
| `theme` | `{ accent?: string, dark?: boolean }`? | 主题色 |
| `home` | string | 首页的 page id |
| `pages[]` | `{ id, title, tab?, blocks[] }` | 页面 |
| `blocks[].kind` | `header \| text \| notice \| stats \| list \| feed \| chat \| buttons \| divider` | 内容块类型，各类型字段不同 |
| `action` | `{ go?, effects?, when?, lockedHint?, toast?, once?, cooldownDays?, log? }` | 按钮 / 列表项点击行为 |
| `effects[]` | `{ metric, delta }` / `{ flag, delta, set? }` / `{ rel, delta }` | 对作品属性 / 标记 / 关系的影响 |
| `when[]` | `{ metric \| flag \| rel, op: "gte" \| "lte", value }` | 可执行条件 |

完整类型定义见前端 `Romance/src/mods/kkmod/phoneApp.ts`。

**请后端**：

1. `content` 按 **JSON 对象原样存取**，不要只取 `text`，也不要丢弃未知字段。体积比原来大（多页时可能几十 KB），如有长度限制请告知上限。
2. **兼容旧数据**：已有应用的 `content` 仍是 `{ text }`，前端打开时会自动转换，后端**不需要迁移**，读取时原样返回即可。
3. 审核后台如需预览，按 `schema === "kkapp@1"` 判断新格式。
4. 前端保存前已做格式校验；后端如需校验，最少检查 `schema`、`home`、`pages` 是否存在。

## 3. 玩法 Mod 上传包新增「文件目录」（新增，完整文档未写）

上传接口 `POST /api/components/kkmod/upload`（已有）的 `package.payload` 里新增两个字段，原有的 `payload.mod` **保留不变**（旧客户端继续读它）：

```json
{
  "payload": {
    "mod": { "...": "原有完整 mod，不变" },
    "format": "kkmod-files@1",
    "files": {
      "npcs/dwarf.json": { "id": "dwarf", "name": "..." },
      "rooms/home.json": { "...": "..." },
      "tuning.json": { "...": "..." }
    }
  }
}
```

- `files` 是「路径 → 内容」的映射，规则类似游戏材质包：同路径覆盖原版，新路径为新增。
- **请后端**：`payload` 整体原样保存，不要裁掉 `format` / `files`；包体积会增大（约为原来的 2 倍），如有上传大小限制请告知。

## 4. 作品正文 / 存档里的新字段（原样存取即可）

作品正文走 `PUT .../drafts/romance/{fileId}/content` 的 `mod.content`；存档目前在浏览器本地，以后上云时一并保存。

| 位置 | 字段 | 类型 | 说明 |
|------|------|------|------|
| `mod.content` | `phoneCommSkin` | `"lvxin" \| "chuanxun"`? | **新增**。通讯 App 皮肤：`lvxin` 绿信（默认），`chuanxun` 传讯（古风 / 仙侠）。缺省 = 绿信 |
| `mod.content` | `schedule` | `{ cats?: { id, label?, hint?, color?, hidden? }[] }`? | 日程板分类配置；`id` 只会是 `work/lesson/job/rest/social`（详见完整文档 5.4） |
| `mod.content` | `metricBind` | `{ fame?, reputation?, blackFans?, stamina?: string }`? | 名气等数值绑定到作者自定义属性 id（详见完整文档 3.5 / 5.4） |
| `mod.content` / `state` | `timeLimit` | TimeLimit? | 改称「结算时限」，不叫「主线时限」（完整文档 15.2） |
| `mod.content` / `state` | `gradeDims` | GradeDim[]?，最多 4 条 | 不设时按建角属性自动生成，不再有内置四项（完整文档 15.3） |
| `mod.playModInstalls[]` | `installedAt` | string?（ISO 日期） | 安装玩法 Mod 时写入（完整文档 10.2） |
| `state.phone` | `msgPref` | `Record<personId, "active" \| "quiet" \| "block">`? | 玩家逐人设置的消息权限；缺省 = 随剧情 |

**请后端**：如果对 `mod.content` 有字段白名单或清洗逻辑，请放行以上字段；没有校验则无需改动。
