## 1. 背景与目标

### 1.1 业务需求摘要

| 能力域 | 说明 |
|--------|------|
| **角色管理** | 管理员可分配：创作者（普通）、创作者激励（官方认证）、运营者 |
| **默认注册** | 新用户注册即为 **创作者（普通）** |
| **官方认证** | 管理员升级 **创作者激励（官方认证）**，头像 **V 标** |
| **创作者统计** | 本人作品：总览 + 单作品下钻（10 项指标） |
| **运营者统计** | 全站 **已公开** 作品：总览 + 单作品下钻（只读；不含未公开作品） |
| **运营者推广/任务** | **登录即见**：推广管理、每日任务管理、**拉新总览**（全站所有推广任务完成情况）；无需领取任务 |
| **创作者推广/任务** | **沿用现有逻辑，不修改**（用户中心每日任务、复制推广链接、`/promotions` 等） |
| **管理员** | 分配角色/权限、菜单控制 |

### 1.2 创作者 / 运营者统计维度（总览 + 单作品）

| 维度 | 总览 | 单作品下钻 |
|------|:----:|:----------:|
| 浏览量（PV/UV） | ✅ | ✅ |
| 点赞数 | ✅ | ✅ |
| 转发数 | ✅ | ✅（需新增埋点，见 §3.6） |
| 玩家年龄 / 性别 | ✅ 聚合 | ✅ 聚合 |
| 活跃时间段 | ✅ | ✅ |
| 评论 | ✅ | ✅ 列表 |
| 游玩次数 / 时长 | ✅ | ✅ |
| 消费 | ✅ | ✅ |
| 评价 | ✅ | ✅ 分布 + 列表 |

### 1.3 非目标（本期默认）

- 运营者编辑/下架他人作品（默认只读）
- 运营者查看 **未公开** 作品统计（已确认不需要）
- **改造创作者侧推广后台 / grant 菜单**（本期不做）
- 小程序完整管理后台（沿用 PC 策略）

## 2. 双维度模型：`role` × `userSegment`

### 2.1 `user.role` — 权限 / 菜单 / API

| 角色 | 标识 | 分配方式 | 说明 |
|------|------|----------|------|
| 创作者（普通） | `creator` | **注册默认** | 本人作品 + 本人数据统计；推广走现有用户端流程 |
| 创作者激励（官方认证） | `creator_verified` | 管理员分配 | 普通创作者能力 + **头像 V** |
| 运营者 | `operator` | 管理员分配 | 全站统计 + **登录即开放**推广/每日任务/拉新总览 |
| 管理员 | `admin` | 手动设置 | 全权限 + 用户角色管理 |

### 2.2 `user.userSegment` — 激励分群（不变）

| 值 | 含义 |
|----|------|
| `normal` | 普通用户 |
| `game_incentive` / `incentive` | 游戏创作激励 |
| `code_incentive` | 邀请激励 |
| `all_incentive` | 创作 + 邀请双激励 |

`role` 管权限菜单；`userSegment` 管激励结算，二者分离。

### 2.3 官方认证与 V 标

- **V 标**：`role === 'creator_verified'`（或 `is_official_creator = 1`）
- **激励开通**：可选同步 `userSegment`，与认证可独立操作

## 3. 推广 / 每日任务 / 拉新 — 权限模型

### 3.1 运营者 — 登录即开放（仅运营者 + admin 新增后台）

```text
operator 登录后立即可见：
  ├── 全站运营统计（总览 + 单作品下钻）
  ├── 推广管理（全站）
  │     ├── 发布 / 编辑 / 下架推广活动
  │     ├── 审核用户投稿
  │     └── 首页 ticker 配置
  ├── 每日任务管理（全站）
  │     ├── 创建 / 编辑 / 删除任务配置
  │     └── 查看各任务配置、全站领取情况
  └── 拉新总览（全站）                    ← 运营者专属新增
        ├── 所有推广类每日任务的完成情况汇总
        ├── 按任务 / 按游戏 / 按用户维度下钻
        ├── 有效邀请数、注册转化、链接点击
        └── 每个用户（推广者）的任务进度与拉新明细（脱敏）

无需领取任务；role === 'operator' 即可。
```

**与 admin 差异**：运营者 **不含**公告、轮播、题材、积分、激励结算、会员、文档、分成等 Tab；仅上述三块 + 运营统计。

### 3.2 创作者 — 沿用现有逻辑（本期不改造）

```text
creator / creator_verified 继续使用现有能力，不新增后台菜单：
  ├── 用户中心 Profile → 每日任务（领取、进度、复制推广链接）
  ├── /promotions → 推广活动投稿
  ├── gamePromotionApi → 游戏推广归因、拉新（已有）
  └── docs/GAME-PROMOTION-DAILY-TASK-PLAN.md 中已定义流程

本期不新增：
  ✗ creator_promotion_grants 表
  ✗ /creator/promotion 后台路由
  ✗ 创作者版推广管理 / 每日任务管理菜单
```

**说明**：创作者在 Profile 领取「游戏推广任务」后，仍按 **现有** 每日任务 + 推广链接逻辑运作；运营者在 **拉新总览** 中查看全站汇总即可。

### 3.3 运营者 vs 创作者（推广域）

| 能力 | 运营者 | 创作者（现有逻辑） |
|------|:------:|-------------------|
| 发布全站推广活动 | ✅ | ❌ |
| 全站每日任务 CRUD | ✅ | ❌ |
| 拉新总览（全站所有任务完成情况） | ✅ | ❌ |
| 用户中心领取任务 / 复制推广链接 | 可选 | ✅（已有） |
| 本人邀请进度 | — | ✅ Profile / 任务进度（已有） |

### 3.4 拉新总览 — 指标与数据源（运营者）

| 指标 | 说明 | 数据源 |
|------|------|--------|
| 任务完成率 | 各推广类 daily_task 领取人数 vs 达标人数 | `user_daily_task_progress` 等 |
| 有效邀请总数 | 全站 valid 邀请 | `game_promotion_invitations` |
| 按用户明细 | 推广者昵称 + 脱敏手机号（中间 4 位 `****`）+ 邀请/转化数 | `game_promotion_invitations` + `user` |
| 按游戏聚合 | 各 `game_file_id` 推广效果 | 归因表 |
| 链接点击 | promo 链接 PV | 推广点击日志 / analytics |
| 时间趋势 | 日/周拉新曲线 | 按 `event_date` 聚合 |

详见 `docs/GAME-PROMOTION-DAILY-TASK-PLAN.md`。

### 3.5 数据模型（本期）

**仅需扩展 `user.role`**，**不需要** `creator_promotion_grants`。

拉新总览只读聚合，复用现有每日任务与推广邀请表；必要时新增 **汇总视图 / 索引**，不新增 grant 表。

### 3.6 转发埋点（「转发数」统计）— 已确认

**计入规则**

| 触发场景 | 事件 | 是否计入 |
|----------|------|:--------:|
| 用户点击「复制分享链接」且 **复制成功** | `game_share` / `action=copy_link` | ✅ |
| 用户点击 **微信 / 系统分享** 按钮 | `game_share` / `action=native_share` | ✅ |
| 仅打开详情页、未实际分享 | — | ❌ |

**上报字段**

```json
{
  "event_type": "game_share",
  "game_file_id": "xxx",
  "user_id": "可选",
  "share_channel": "copy_link | wechat | other",
  "source": "game_detail | ..."
}
```

写入 `user_analytics_events`（扩展 `event_type`）或独立计数表；按 `game_file_id` + 日聚合，供创作者 / 运营者统计 API 使用。

### 3.7 运营者作品范围

**已确认**：运营者统计 **仅包含已公开作品**（`games.is_public = 1`）。  
未公开 / 下架作品 **不纳入** 全站总览与单作品下钻；API 查询统一加 `WHERE is_public = 1`（运营者访问未公开 `fileId` 返回 404）。

### 3.8 拉新总览 — 按用户展示（已确认）

| 字段 | 规则 |
|------|------|
| 昵称 | 展示 `user.nickname`，空则显示「未设置昵称」 |
| 手机号 | 展示脱敏号：**中间 4 位 `****`**，例如 `138****5678`（前 3 + 后 4） |
| 无手机号 | 显示「—」 |

仅 **运营者 / admin** 在拉新总览可见；不对普通创作者开放他人手机号。

## 6. 后端 API 设计

### 6.1 鉴权

```text
requireRole('creator', 'creator_verified')  → 创作者统计 scope=own
requireRole('operator', 'admin')            → 运营统计 + 推广 + 每日任务 + 拉新总览 scope=all
requireAdmin()                              → 用户角色 + 全量 admin
```

### 6.2 创作者统计 API（新增）

| 方法 | 路径 |
|------|------|
| GET | `/api/creator/stats/overview` |
| GET | `/api/creator/stats/works` |
| GET | `/api/creator/stats/works/:fileId` |
| … | 评论 / 玩家画像等 |

### 6.3 运营者 API（新增 + 鉴权改造）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/operator/stats/overview` | 全站汇总（**仅公开作品**） |
| GET | `/api/operator/stats/works` | 全站作品列表（`is_public = 1`） |
| GET | `/api/operator/stats/works/:fileId` | 单作品明细（未公开 404） |
| GET | `/api/operator/recruitment/overview` | **拉新总览**：全站任务完成汇总 |
| GET | `/api/operator/recruitment/tasks` | 按任务维度：领取数/完成数/邀请数 |
| GET | `/api/operator/recruitment/users` | 按用户：昵称 + 脱敏手机号 + 任务完成情况 |
| * | `/api/admin/promotions/*` | 鉴权改为 `operator` \| `admin` |
| * | `/api/admin/daily-tasks/*` | 鉴权改为 `operator` \| `admin` |

### 6.4 创作者推广 API — 不改动

以下 **保持现有路径与逻辑**，仅确保 `role` 迁移后仍可用：

- `/api/auth/daily-tasks/*`
- `/api/auth/promotion/*`
- `/api/auth/promotions/*`（用户投稿）

### 6.5 管理员 — 用户管理

| 方法 | 路径 |
|------|------|
| GET | `/api/admin/users` |

## 7. 数据迁移

```sql
-- role: creator | creator_verified | operator | admin
UPDATE user SET role = 'creator' WHERE role = 'user' OR role IS NULL OR role = '';

ALTER TABLE user ADD COLUMN is_official_creator INTEGER NOT NULL DEFAULT 0;
UPDATE user SET is_official_creator = 1 WHERE role = 'creator_verified';
```

**不需要** `creator_promotion_grants` 表。

**JWT** 扩展 `role`、`isOfficialCreator` 即可；无需 `hasCreatorPromotionGrant`。
