> **文档类型**：前后端联合技术方案（前端仓库归档）

## 1. 背景与目标

### 1.1 业务需求摘要

| 能力域 | 说明 |
|--------|------|
| **角色管理** | 管理员可分配：创作者（普通）、创作者激励（官方认证）、运营者 |
| **默认注册** | 新用户注册即为 **创作者（普通）** |
| **官方认证** | 管理员升级 **创作者激励（官方认证）**，头像 **V 标** |
| **创作者统计** | 本人作品：总览 + 单作品下钻（10 项指标） |
| **运营者统计** | 全站 **已公开** 作品：总览 + 单作品下钻（只读；不含未公开作品） |
| **运营者推广/任务** | **登录即见**：推广管理、每日任务管理、**拉新总览** |
| **创作者推广/任务** | **沿用现有逻辑，不修改** |
| **管理员** | 分配角色/权限、菜单控制 |

### 1.2 创作者 / 运营者统计维度（总览 + 单作品）

| 维度 | 总览 | 单作品下钻 | 数据源 / 说明 |
|------|:----:|:----------:|---------------|
| 浏览量（PV/UV） | ✅ | ✅ | `game_statistics` + KV 聚合 |
| 点赞数 | ✅ | ✅ | `game_statistics.like_count` |
| 转发数 | ✅ | ✅ | 新增 `game_share` 埋点（见 §3.6） |
| 玩家年龄 / 性别 | ⏳ | ⏳ | **延后**：需新增用户资料采集（见 §3.9） |
| 活跃时间段 | ✅ | ✅ | `user_analytics_events.event_time` 按小时聚合 |
| 评论 | ✅ | ✅ 列表 | 评价/评论表 |
| 游玩次数 / 时长 | ✅ | ✅ | 次数见 §3.10；时长见 `game_session_duration` |
| 消费 | ✅ | ✅ | 订单 / 积分消耗 |
| 评价 | ✅ | ✅ 分布 + 列表 | `games.rating_avg` 等 |

### 1.3 非目标（本期默认）

- 运营者编辑/下架他人作品（默认只读）
- 运营者查看 **未公开** 作品统计（已确认不需要）
- **改造创作者侧推广后台 / grant 菜单**（本期不做）
- 小程序完整管理后台（沿用 PC 策略）

## 3. 运营者能力与拉新

### 3.1 运营者登录即见（无需任务 grant）

- 推广管理
- 每日任务管理
- **拉新总览**

### 3.2 拉新总览 — 指标与数据源

| 指标 | 说明 | 数据源 |
|------|------|--------|
| 任务完成率 | 各推广类 daily_task 领取 vs 达标 | `user_daily_task_progress` 等 |
| 有效邀请总数 | 全站 valid 邀请 | `game_promotion_invitations` |
| 按用户明细 | 昵称 + 脱敏手机号（中间 4 位 `****`）+ 邀请/转化 | 同上 + `user` |
| 按游戏聚合 | 各 `game_file_id` 推广效果 | 归因表 |
| 链接点击 | promo 链接 PV | 推广点击日志 / analytics |
| 时间趋势 | 日/周拉新曲线 | 按 `event_date` 聚合 |

### 3.3 拉新总览 — 按用户展示（已确认）

| 字段 | 规则 |
|------|------|
| 昵称 | `user.nickname`，空则「未设置昵称」 |
| 手机号 | 中间 4 位 `****`，如 `138****5678` |
| 无手机号 | 显示「—」 |

### 3.4 运营者作品范围（已确认）

运营者统计 **仅包含已公开作品**（`games.is_public = 1`）。未公开作品不纳入；直接访问未公开 `fileId` 返回 404。

### 3.5 数据模型（本期）

仅需扩展 `user.role`，**不需要** `creator_promotion_grants`。

### 3.6 转发埋点（已确认）

| 触发场景 | 事件 | 是否计入 |
|----------|------|:--------:|
| 复制分享链接 **成功** | `game_share` / `action=copy_link` | ✅ |
| 点击 **微信 / 系统分享** | `game_share` / `action=native_share` | ✅ |
| 仅打开详情页、未分享 | — | ❌ |

写入 `user_analytics_events`（扩展 `event_type`）或独立计数表；按 `game_file_id` + 日聚合。

### 3.9 玩家年龄 / 性别（延后）

**现状**：`user` 表无 age/gender；作品内主角设定是剧情角色，**不能**当作真实玩家画像。

**结论**：本期 **不做** 年龄/性别统计展示；后续由产品新增用户资料采集（注册或 Profile 选填/必填）后再开发聚合 API。

### 3.10 游玩次数 / 时长（已确认）

#### 游玩次数

| 项 | 定义 |
|----|------|
| **口径** | `user_analytics_events` 中 `event_type = 'game_entry'` 的条数 |
| **触发时机** | 用户创建 **游玩 session** 时（后端 `gamesSession.js` → `trackGameEntry`） |
| **总览 PV** | `COUNT(*)` WHERE `game_file_id IN (...)` AND `event_type = 'game_entry'` |
| **总览 UV** | `COUNT(DISTINCT user_id)` 同上（仅登录用户） |
| **单作品** | 同上，加 `game_file_id = ?` |

**注意**：不使用 `game_statistics.conversion_count` 作为游玩次数。`conversion_count` 是「详情 → 开玩」的 **日去重转化数**（同一用户同一作品同一天最多计 1 次），语义不同。

#### 游玩时长

| 项 | 定义 |
|----|------|
| **口径** | `event_type = 'game_session_duration'` 的 `duration_seconds` 求和 |
| **上报** | 前端 `useGameDurationTracking`，约每 25s 批量上报 |

#### 活跃时间段

对 `game_entry` 或 `game_session_duration` 的 `event_time` 取小时（0–23），按作品聚合分布。

## 6. 后端 API 设计（摘要）

### 6.1 鉴权

```text
requireRole('creator', 'creator_verified')  → scope=own
requireRole('operator', 'admin')            → scope=all（仅 is_public=1）
requireAdmin()                              → 用户角色管理
```

### 6.2 统计 API（新增）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/creator/stats/overview` | 创作者总览 |
| GET | `/api/creator/stats/works/:fileId` | 单作品（含 playCount = game_entry） |
| GET | `/api/operator/stats/overview` | 运营总览（仅公开作品） |
| GET | `/api/operator/stats/works/:fileId` | 单作品明细 |
| GET | `/api/operator/recruitment/*` | 拉新总览 |

**游玩次数查询示例（单作品）**：

```sql
SELECT COUNT(*) AS play_count_pv,
       COUNT(DISTINCT user_id) AS play_count_uv
FROM user_analytics_events
WHERE game_file_id = ?
  AND event_type = 'game_entry'
  AND event_date >= ? AND event_date <= ?
```

## 7. 实施阶段（摘要）

1. **Phase 1**：角色 + V 标 + 用户管理  
2. **Phase 2**：创作者统计 MVP（含 game_entry 游玩次数、时长；不含年龄性别）  
3. **Phase 3**：运营者全站统计（仅公开作品）  
4. **Phase 4**：运营推广三件套 + 拉新总览 + 转发埋点
