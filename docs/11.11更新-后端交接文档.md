## 模块一：游戏详情页

### 1.0 改动摘要

- 点赞、收藏改为点击后立即变色并更新数字，接口失败会恢复原状并提示；成功后弹出「已点赞 / 已收藏」等提示。
- 未登录时点赞或收藏，登录后会自动补做一次；改为等拿到当前账号的点赞和收藏状态后再执行，避免切反。
- 登录后同步点赞数和收藏数。
- 读档时不再整页转圈。
- 互动影游付费错误、上架状态说明等文案改为中英文配置。
- 文字游戏（TXT）详情页入口改为「开始游戏」「读取存档」两个按钮（见 1.9）；剧情简介旁重复的「读取存档」已删除。
- 作品详情类型里的 `reaction` 放宽为 `string | number | boolean | null`，前端兼容多种写法，见 1.1。

### 1.2 点赞作品 `POST /auth/games-stats/like`

请求：`{ fileId }`。行为：**切换**（已赞→取消，未赞→点赞）。

| 返回字段 | 类型 | 必填 | 待后端确认 |
|---|---|---|---|
| `isLiked` | boolean | 是（切换后的最终态） | |
| `likeCount` | number | 是（切换后的总数） | |
| `fileId` / `message` | string | 否 | |

⚠ 建议另提供幂等接口 `{ fileId, liked: boolean }`（设置为指定状态）。这样前端补发的操作不会因为状态不同步而把点赞切反。目前前端在 300ms 防抖内合并连点，并等登录态同步后才补发。

### 1.3 收藏作品 `POST /auth/games/favorites/toggle`

请求：`{ fileId }`。行为：切换。

| 返回字段 | 类型 | 必填 | 待后端确认 |
|---|---|---|---|
| `isFavorited` | boolean | 是 | |
| `favoriteCount` | number | ⚠ 希望必返（缺省时前端按乐观值 ±1） | |

幂等接口建议同上。

### 1.4 评分 / 评论

| 接口 | 说明 |
|---|---|

### 1.5 更新日志 `GET /auth/games/:fileId/update-logs`

返回 `{ list: GameUpdateLogItem[]; latest: GameUpdateLogItem | null }`，元素字段为 `id, fileId, note, createdBy, createdAt(ISO)`。

### 1.6 游玩状态 `GET /auth/games/:fileId/play-status`

返回 `{ hasContinueState: boolean; hasSave: boolean }`。

- 文字游戏（TXT）：点「读取存档」时请求一次；`hasContinueState=true` 时在存档列表顶部显示「自动存档 · 云端」位（见 1.9）。
- 其他类型：仍用于决定显示「继续体验」还是「开始体验」，以及是否弹出开始方式选择。

⚠ 前端把 `hasContinueState` 当作「云端有自动存档（上次进度）」。如果两者含义不同，请告知。

### 1.7 互动影游付费

| 接口 | 说明 |
|---|---|
| `GET /interactive-video/games/:fileId/access` | 返回 `{ config, access }`；`config.mode` 为 `'free'\|'buyout'\|...`，`access.hasBuyout` 表示是否已买断 |
| `POST /interactive-video/games/:fileId/unlock` | 请求 `{ purchaseType: 'buyout'\|'directory', currency: 'points'\|'diamonds'\|'free', directoryId? }`；返回 `{ access, alreadyOwned }` |

**错误码**（前端已按 code 映射中英文文案，见 `gameDetail.ivgErrors`）：
`INSUFFICIENT_POINTS`、`INSUFFICIENT_DIAMONDS`、`PAYMENT_METHOD_UNAVAILABLE`、`BUYOUT_NOT_FOR_SALE`、`DIRECTORY_NOT_FOR_SALE`、`FREE_UNLOCK_UNAVAILABLE`、`INVALID_CURRENCY`、`INVALID_PURCHASE_TYPE`、`INVALID_PARAM`、`INVALID_PURCHASE_PARAM`、`AUTH_REQUIRED`、`NOT_FOUND`、`FORBIDDEN`、`MONETIZATION_ERROR`。
⚠ 请务必返回 `code`。只返回英文 `message` 时，前端只能按固定字符串匹配；新增错误码请同步告知前端。

仅对文字游戏（`gameMode=TXT`）生效；小说、互动影游、CUSTOM / ST / ROMANCE 不变。

| 按钮 | 行为 | 接口（均沿用现有） |
|---|---|---|

### 2.2 新增字段：人物线路 `CreationPath`

位置：世界观模组 JSON → 建角 → 人物线路列表里的每一项。

| 字段 | 类型 | 必填 | 用途 | 待后端确认 |
|---|---|---|---|---|
| `storylineId` | string | 否 | 关联的主线 id。玩家选这条线路时，按这条主线的节点顺序画路线图（优先使用） | |
| `routeNodes` | string[] | 否 | 作者手写的路线节点。没关联主线、或主线里没有节点时使用 | |

⚠ 请确认保存和发布作品时，不会按白名单把这两个新字段过滤掉。老作品没有这两个字段也能正常显示，只是不出路线图。

### 2.3 依赖字段：世界题材

通讯 App 显示「绿信」还是「传讯」，按下面的顺序判断：

1. 模组里的 `phoneCommSkin`（`'lvxin'` / `'chuanxun'`，作者在编辑器里手动选）
2. 模组里的 `commsSkin`
3. 题材 `themeCode` / `themeLabel`（包含「古代 / 仙侠 / 宫斗 / 玄幻 / 武侠」就用「传讯」）
4. 前面都没有时，看世界名称

平台作品详情里的 `theme_tag_ids` / `theme_tag_names` / `theme_tag_codes` 会补进模组的题材字段，只补空的，不覆盖作者已经填的。
⚠ 希望后端在作品详情里返回 `theme_tag_codes`（比如 `ancient`、`xianxia`），这样就不用靠中文题材名去匹配。

#### 2.4.1 商店列表 `GET /api/components/shelf?installed=slug1,slug2`

「添加玩法」弹窗打开时调用一次。有加载中 / 失败重试 / 无数据三种状态。

- `data` 可以是数组，也可以是 `{ items: [] }`，两种前端都兼容。
- 带 `Authorization: Bearer <token>` 时请填 `purchased`，且响应不能被缓存。
- 官方玩法（出行与交通、座驾包等）也要从这里返回，`slug` 保持原值（如 `pack-transport`），老作品的安装记录才能对上。

| 字段 | 类型 | 必填 | 前端用途 | 待后端确认 |
|---|---|---|---|---|
| `id` / `slug` | string | 是 | 安装记录、依赖都按 slug 匹配 | |
| `name` / `description` | string | 是 | 名称、一句话说明 | |
| `detailMd` | string | 否 | 详情页「玩法说明」 | |
| `previewImages` | string[] | 否 | 详情页预览图，**只显示 http(s) 地址**，为空时不显示预览区 | |
| `authorDisplayName` | string | 是 | 作者 | |
| `iconUrl` | string | 否 | ⚠ 新增：图标图片地址。前端不再插入作者上传的 `iconSvg`（有脚本注入风险），没有 `iconUrl` 就显示名称首字 | |
| `version` | string | 是 | 写入安装记录 | |
| `dependsOn` | string[] | 否 | ⚠ 新增：依赖的 slug（「添加（含依赖）」）。可从 kkmod `manifest.dependencies` 取 | |
| `editorPanels` / `defaultNavLabel` / `needsNavEntry` | — | 否 | 安装后编辑器配置区、底栏 | |

「推荐」排序规则：已添加玩法的扩展包 > 已添加玩法需要的包 > 适合本作品题材 > 官方推荐 > 安装数；题材不符的靠后，已添加的排最后。

#### 2.4.2 登记安装 `POST /api/components/:id/install`

- body：`{ "gameFileId": string }`，需登录；作品没有 `gameFileId`（未保存过）时前端不调用。
- 每添加一个包（含一并添加的依赖）调用一次，用于累计 `stats.installGames`；同一作品重复添加请勿重复计数。
- 前端不等结果，失败不影响已添加。

#### 2.4.3 作者上传预览图

位置：创作游戏 → 玩法 Mod，对话生成并保存后。

- **原来**：保存后自动上传 `.kkmod`，**完全没有预览图**，所以商店里作者包没有真实预览图。
- **现在**：保存后不再自动上传，先显示「商店预览图」区域，作者上传 1–6 张图片，**少于 1 张时上传按钮不可点**。可以删除重传；继续编辑旧玩法时会带出已有的预览图。
- 单张图片上传：沿用现有图床接口 `POST /api/auth/platform-apps/upload`（`multipart/form-data`，字段 `file`），读返回的 `data.imageUrl`。
- 上传玩法包：`POST /api/components/kkmod/upload` 的 body 新增顶层字段：

```json
{ "filename": "xxx.kkmod", "package": { }, "engineVersion": "1.0.0", "previewImages": ["https://..."] }
```

| 字段 | 类型 | 必填 | 用途 | 待后端确认 |
|---|---|---|---|---|
| `previewImages` | string[] | 是 | 作者上传的预览图 URL（1–6 张），写入组件 `previewImages` | |

运营后台（主站 `src/components/admin/AdminPlayModManager.tsx`）：原来的「预览图 URL」文本框改成直接上传图片，运营可以补传、删除作者的预览图（同样 1–6 张），走同一个图床接口，保存仍用 `PUT /api/admin/components/:id` 的 `previewImages` 字段。

⚠ 请后端：保存这个字段；提审 / 上架时校验至少 1 张；`GET /api/components/mine` 每项返回 `previewImages`（继续编辑时带出）。如果希望玩法预览图用单独的上传接口，告诉前端路径即可替换。

### 5.1 前端已完成：扣费接口新增请求字段

### 5.2 后端要做：所有 AI 扣费统一迁移到新计费（已定）

**决定：所有 AI 调用的计价、扣费、退款统一走新计费逻辑（AI 模型中心的计价版本 + 计费调用记录），不保留两套并存。** 老的「按 `engineId` 扣积分」方式下线。

1. **统一入口**：`play/complete`、`world-gen/complete`、`world-gen/refund`、`images/generate`、TXT 文档解析，全部按新计费的计价版本计算成本和用户扣费，并写入计费调用记录（`usage/attempts` 的数据源），每次上游尝试一条。
2. **下线老逻辑**：去掉 `world-gen/complete` 按 `engineId` 固定扣分、`images/generate` 走老积分账本的扣费路径；`engineId` 字段前端暂时照发，仅作兼容，**不再参与计价**。
3. **退款也走新逻辑**：`world-gen/refund` 不再按前端上报的 `points` 退款，改为按 `traceGroupId` 找到这次任务在新计费里的扣费流水，由后端计算应退金额、幂等退款，退款流水指回原扣费流水。前端上报的 `points` 只作核对，不一致时以后端为准并记录差异。
4. **扣费流水可互查**：用户钱包流水（织梦豆 / KK 币）中每一笔 AI 扣费 / 退款必须带 `attemptId` 与 `clientRequestId`；计费调用记录反向带 `ledgerTxnIds`。
5. **响应保持兼容**：三个接口成功后仍返回 `pointsDeducted`、`remainingPoints`（前端用来更新顶栏余额、汇总退款），数值改为新计费的实际扣费结果。
6. **历史数据**：迁移上线前的老积分账本 AI 流水，导入为计费调用记录（标记 ⚠ `migratedFrom=legacy_points_ledger`，保留原流水 id），能补的字段照补、补不了的记 `null` 并标明，不得编造 token 或成本；导入后仪表盘历史区间才完整。
7. **切换与核对**：请提供上线时间点；上线后抽样核对一段时间（新计费扣费 = 用户钱包实际变动），核对结果写进本文。

### 5.3 溯源总原则（适用于下面每个字段）

- **来源可查**：每个字段写明来自哪里（前端请求 / 上游响应 / 计价版本 / 扣费流水 / 后端计算）。
- **计算可复算**：后端计算出来的数（成本、扣费）必须同时保存参与计算的原始值和所用计价版本，任何人拿明细能复算出同样结果。
- **不可篡改**：明细写入后只追加不修改；更正用新增「调整 / 退款」记录，并指向原记录。
- **可下钻**：概览、趋势、排行、聚合表里的每一个数字，都能点开看到组成它的调用明细列表（相同筛选条件），明细能看到对应的扣费 / 退款流水。
- **可关联**：一次用户操作 → `clientRequestId` → 若干上游尝试（`attemptId`）→ 扣费流水（`ledgerTxnId`）→ 退款流水（指回原流水），链路完整。

| `platformSource` / `gatewayRoute` / `modelId` | 后端路由结果 | 记录**实际**调用的网关与模型（发生回落时与 `routeId` 不同，需能看出来） |
| ⚠ `upstreamRequestId` | 上游响应 | 上游返回的请求 / 响应 id，用于与上游账单逐条对账 |
| `status` / `failureCode` / `failureMessage` | 后端 | 失败须带上游原始错误码（截断保存），便于判断是上游问题还是平台问题 |
| `startedAt` / `finishedAt` / `createdAt` | 后端时钟 | 统一时区（UTC 存储，标明展示时区） |
| `inputTokens` / `outputTokens` / `cachedInputTokens` | **上游响应的 usage** | 必须取上游返回值，不得自行估算；上游未返回时记 `null` 并标注 `usageSource=estimated|missing` |
| `imageCount` / `imageAspectRatio` | 上游响应 + 请求参数 | 以上游实际返回张数为准 |
| `billingVersionId` / `billingModelRateId` | 计价版本 | 指向调用发生时生效的版本，版本内容只读可查 |
| `inputPriceX10000` / `outputPriceX10000` / `cachedInputPriceX10000` / `imageUpstreamCostYuanX10000` / `imageUserBasePriceKkX10000` | 计价版本快照 | 写入当时的单价快照，后续改价不影响历史 |
| `platformCostMicroYuan` | 后端计算 | ⚠ 增加 `costFormula`（如 `in×inPrice + out×outPrice + cached×cachedPrice`）或返回参与计算的全部输入，前端可在明细里展示复算过程 |
| `currencyType` / `userChargeMicroUnits` / `allocatedUnits` / `billedToUser` | 后端计算 + 扣费流水 | ⚠ 增加 `ledgerTxnIds: string[]`（本次对应的扣费流水 id）；`billedToUser=false` 时必须给 ⚠ `notBilledReason`（如 `free_quota` / `failed_no_charge` / `refunded` / `author_preview` / `operator`） |
| `settlementStatus` | 扣费流水 | 写明枚举含义；退款后为 `refunded` 并带 ⚠ `refundTxnId`、⚠ `refundReason` |
| ⚠ `memberDiscountPercent` | 用户会员状态快照 | 调用时的会员折扣，复算扣费用 |

### 6.1 交互

### 6.2 请求怎么带线路

| 玩法 | 带法 | 后端要求 |
|---|---|---|
| Romance | 原有：请求体 `routeId`（见 `Romance/docs/后端对接-字段与接口清单.md` 第 14 节） | 已有约定 |

- 只有玩家**主动选了**线路才追加；未选 = 不带参数 = 平台默认线路。

- 线路不存在 / 已下架 / 维护中：请与 Romance 一致处理（回落默认或 409 `ROUTE_UNAVAILABLE`，二选一告知）。
- 计费：按所选线路的计价与倍率扣费，并在计费调用记录里写入 `routeId`（见 5.4），溯源要求同模块五。
