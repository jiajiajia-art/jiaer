## 1. 这篇文档解决什么问题？

创作者在 Step 1 输入一句创意，例如：

> **朱元璋60岁生日**

系统会自动生成：

- **世界观**（时代背景、开场、文风…）
- **角色档案**（朱元璋、朝臣、皇室成员…）
- **场景**（万寿殿、内宫、京城街道…）

但这三步**不够**支撑稳定叙事。还缺一类配置：**补充提示词**（`morePromptForms`，侧栏「+ 补充提示词」）。

本文说明：

1. **除了世界观 / 角色 / 场景，还要往 morePrompt 里补什么？**
2. **每类提示词怎么写？**（关键词、是否始终生效、内容写什么）
3. **用「朱元璋60岁生日」走一遍完整示例**
4. **一句话生成结束时，如何自动写入 5～6 条草稿**（研发附录）

## 2. 四块内容各自管什么？

| 模块 | 侧栏入口 | 解决什么问题 | 典型内容 |
|------|----------|--------------|----------|
| **世界观** | Step 2 世界观表单 | 这个世界是什么 | 时代背景、开场白、开场剧情、文学风格 |
| **角色档案** | Step 3 角色 | 有哪些人 | 姓名、外貌、职业、性格长文 |
| **场景** | Step 4 场景 / BGM | 有哪些舞台 | 地点名称、场景描述、解锁条件 |
| **补充提示词** | 侧栏「+ 补充提示词」 | **对话进行到什么节点时，AI 多遵守什么、多知道什么** | 礼仪规则、角色口吻、场景氛围、剧情节点事实 |

### 2.1 一句话记忆

- **世界观 / 角色 / 场景** = 静态档案（「有什么」）
- **morePrompt** = 动态规则（「什么时候 AI 必须多知道一点」）

### 2.2 morePrompt **不要**做什么

| 不要做 | 原因 |
|--------|------|
| 把整段 `background` 再抄进 morePrompt | 世界观里已有，浪费 token |
| 把 NPC 长人设全文贴进每条 | 角色档案里已有；morePrompt 只摘**对话口吻 + 关系**短规则 |
| 用玩家不会说的词当关键词 | 例如「皇帝寿辰大典」——对话里很难原样出现，永远触发不了 |
| 在 content 里写「将要发生」的剧透 | 应写**已发生**的事实，等关键词出现后再告诉 AI |

## 3. 除三步之外：建议补充的 6 类提示词

一句话生成完成后，建议**自动**往 `morePromptForms` 写入 **5～6 条**（上限仍为 10 条，创作者可再加）。

| # | 类型 | 始终生效 | 关键词（title） | 内容（content）写什么 | 侧栏描述（≤15字） |
|---|------|----------|-----------------|----------------------|-------------------|
| 1 | **时代与称谓规则** | ✅ 是 | 展示用，如 `大明礼仪` | 时代礼仪、称谓、禁忌、叙事视角 | 如「大明宫廷礼仪」 |
| 2 | **玩家身份与立场** | ✅ 是 | 展示用，如 `玩家身份` | 玩家是谁、职权边界、能/不能做什么 | 如「玩家：近臣身份」 |
| 3 | **核心人物口吻** | ❌ 否 | 人名，如 `朱元璋` 或 `朱元璋,皇上` | 该角色性格、说话方式、对玩家态度 | 如「角色：朱元璋」 |
| 4 | **关键配角口吻** | ❌ 否 | 配角名，如 `马皇后,太子` | 配角性格、与皇帝/玩家关系（按已生成 NPC） | 如「角色：马皇后」 |
| 5 | **场景进入规则** | ❌ 否 | 场景名，如 `万寿殿,寿宴` | 进入该场景时的氛围、礼仪、在场人物 | 如「场景：万寿殿」 |
| 6 | **剧情节点事实** | ❌ 否 | 对话会出现的短语，如 `万寿节,贺寿,献礼` | **已发生**的流程或状态（见 §5 原则） | 如「剧情：万寿节」 |

### 3.1 条数配比（默认）

| 类型 | 建议条数 |
|------|----------|
| 始终生效（#1 + #2） | **2 条** |
| 核心人物（#3） | **1 条** |
| 场景（#5） | **1 条** |
| 剧情节点（#6） | **1～2 条** |
| 配角口吻（#4） | **0～1 条**（视 NPC 数量与创意复杂度） |
| **合计** | **5～6 条** |

### 3.2 字段速查（编辑器 ↔ 运行时）

| 编辑器标签 | 数据字段 | 作用 |
|------------|----------|------|
| 关键词 | `title` | 触发型：逗号分隔，命中任一词即注入 `content` |
| 描述 | `description` | 仅侧栏副标题，≤15 字，**不参与匹配、不注入 LLM** |
| 内容 | `content` | 命中或始终生效时，写入叙事 LLM 的 system prompt |
| 始终生效 | `constant` | `true` = 每轮注入，不扫关键词 |

## 4. 完整示例：「朱元璋60岁生日」

### 4.1 前提（Step 1 已生成）

假设一句话生成已产出：

- **世界观**：洪武年间，万寿节筹备，玩家为近臣
- **角色**：朱元璋、马皇后、太子、礼部尚书等
- **场景**：万寿殿、内宫、京城街道等

下面为建议自动写入的 **6 条** `morePromptForms`。

### 4.2 条目一览

|---|------|----------|--------|----------|

### 4.4 生成后侧栏预期

```
补充提示词
├── 大明礼仪          大明宫廷礼仪      ← 始终生效
├── 玩家身份          玩家：近臣身份    ← 始终生效
├── 朱元璋            角色：朱元璋      ← 关键词触发
├── 万寿殿,寿宴       场景：万寿殿      ← 关键词触发
├── 万寿节,贺寿       剧情：万寿节      ← 关键词触发
└── 献礼,寿礼         剧情：献礼        ← 关键词触发
```

创作者可在此基础上新增，例如：

| 关键词 | 描述 | 内容方向 |
|--------|------|----------|
| `朱元璋赏赐` | 封赏剧情 | 已发生的具体赏赐内容（参考 [触发规则与示例](./TXT-morePromptForms-触发规则与示例.md)） |

## 5. 编写原则（策划 / LLM 自动生成都适用）

### 5.1 关键词怎么选

| 规则 | 说明 | 示例 |
|------|------|------|
| 用对话里会出现的**连续字** | 子串匹配，不是语义相近 | ✅ `献礼`　❌「呈上寿礼」 |
| 多个词用逗号分隔 | 命中**任意一个**即可 | `万寿节,贺寿` |
| 优先用已生成的人名 / 场景名 | 与角色、场景档案一致 | `朱元璋`、`万寿殿` |
| 剧情短语要短 | 来自 `initialPlot` 或创意核心 | `万寿节`、`献礼` |

### 5.2 content 怎么写

| 规则 | 说明 |
|------|------|
| 写短、写准 | 建议每条 80～300 字，忌长篇背景复述 |
| 剧情节点用「已发生」 | 「你已备好寿礼，尚未呈上」✅　「稍后你会被封王」❌ |
| 角色条写口吻与态度 | 不写外貌长描（角色档案已有） |
| 场景条写氛围与礼仪 | 不写场景解锁条件（场景 JSON 已有） |

### 5.3 始终生效不宜过多

| 建议 | 原因 |
|------|------|
| 始终生效 **≤ 2 条** | 每轮都占 token |
| 其余用关键词触发 | 对话到节点再注入，更省、更准 |

## 6. 触发规则（精简版）

未勾选「始终生效」时：只有当前轮 **scanBuffer** 里出现关键词的**连续子串**，才注入 `content`。

**scanBuffer 组成：**

```
本轮玩家输入
+ 最近 8 条对话
+ 读档摘要（如有）
```

| 情况 | 是否触发（关键词 `献礼`） |
|------|---------------------------|
| 玩家输入「准备献礼」 | ✅ |
| AI 上轮写过「开始献礼」 | ✅ |
| 只说「呈上寿礼」 | ❌（不是连续子串 `献礼`） |
| 勾选始终生效 | ✅ 每轮都注入 |

完整对照表见 [TXT-morePromptForms-触发规则与示例.md](./TXT-morePromptForms-触发规则与示例.md)。

## 8. 一句话生成：自动填充策略

### 8.1 当前流水线（已实现）

```
创意 idea → 世界观 → 场景 → 角色 → 写入 R2
```

### 8.2 目标流水线（待开发）

```
创意 idea → 世界观 → 场景 → 角色 → 补充提示词（5～6 条）→ 写入 R2
```

### 8.3 自动生成的输入与输出

| 项 | 说明 |
|----|------|
| **输入** | `idea` 原文 + 已生成的 world / scenes / npcs 摘要 |
| **输出** | `world.json` → `morePromptForms[]`，5～6 条，经 `validateMorePromptForms` 校验 |
| **失败策略** | 软失败：写空数组，不阻断整单生成 |
| **生成后** | 侧栏「补充提示词」自动列出；创作者可编辑、删除、手动新增 |

### 8.4 从创意到条目的映射（给 Prompt 用）

| 创意元素 | 映射到哪类 morePrompt |
|----------|----------------------|
| 时代 / 题材 | #1 时代与称谓规则（始终生效） |
| 玩家角色定位 | #2 玩家身份（始终生效） |
| 主角 / 反派 NPC 名 | #3 核心人物口吻 |
| 其他重要 NPC | #4 配角口吻（可选） |
| 主要场景名 | #5 场景进入规则 |
| 核心事件词（寿宴、战争、赏赐…） | #6 剧情节点事实 |

## 9. 创作者生成后怎么做？

1. 打开侧栏「补充提示词」，检查 5～6 条草稿。
2. **改关键词**：确保玩家对话里真的会说到（试玩时留意是否命中）。
3. **改 content**：把剧透改成「已发生」表述。
4. **删多余常驻**：始终生效超过 2 条时考虑改为关键词触发。
5. **手动加条目**：如 `朱元璋赏赐` 等更细的剧情节点。
6. 保存后试玩验证：到关键剧情时 AI 是否遵守规则。
