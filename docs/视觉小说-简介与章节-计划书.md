## 4. 数据模型

### 4.1 `content.json`（v2 扩展，不破坏 steps）

```json
{
  "contentVersion": "2",
  "steps": [ /* 不变 */ ],
  "chapterIndex": [
    {
      "id": "ch_1",
      "title": "城门搬石",
      "startStepIndex": 0,
      "endStepIndex": 42
    }
  ]
}
```

- `startStepIndex` / `endStepIndex`：闭区间，相对 `steps[]` 下标  
- 章节连续、不重叠、覆盖全文（末章 `endStepIndex = steps.length - 1`）

### 4.2 `meta.json` / API meta

- `chapterCount`: `chapterIndex.length`  
- 简介仍用既有 `description`（≤300）

### 4.3 导出请求体扩展

```ts
{
  title: string;
  description?: string;
  chapters?: Array<{ id?: string; title: string; startStepIndex: number; endStepIndex: number }>;
}
```

创建时：以用户确认后的 `chapters` 写入 `chapterIndex`；缺省则服务端再跑 AI / 兜底。

## 5. 分阶段实施

### P0 — 阅读页简介（小）

| 项 | 内容 |
|----|------|
| FE | `NovelReader` 标题区下增加简介块（复用详情页空态文案习惯） |
| 单测 | 有/无 description 的展示条件（纯函数或轻量组件测） |

**验收**：打开阅读页可见与详情同源简介。

---

### P1 — AI 章节生成 + 导出可编辑

| 项 | 内容 |
|----|------|
| BE | 新服务：根据 session history / replay steps 摘要 → LLM 输出章节 JSON（标题 + 区间） |
| BE | 校验：区间合法、排序、补齐覆盖；失败 → 启发式兜底（`scene_change` / 等分）并生成「第 N 章」类标题 |
| BE | 会话侧 API：`POST .../generate-novel-chapters`（与现有 generate-description 并列） |
| FE | `ExportVisualNovelModal`：加载时 AI 拉章节列表；列表可改标题、可删/合并不做一期（仅改名即可） |
| BE | `novelFromReplay` / `novelCompiler`：写入 `chapterIndex` + `chapterCount` |
| 单测 | 解析清洗、区间校验、兜底切分、compiler 落盘 |

**验收**：导出弹窗必有 AI 章节名；用户改名后落库；新小说 content 含 TOC。

---

### P2 — 阅读页目录（仅此页）

| 项 | 内容 |
|----|------|
| FE | 目录按钮 + 抽屉/浮层列出 `chapterIndex` |
| FE | 点击 → 滚动/定位到对应 step（锚点或 `scrollIntoView`） |
| FE | 无 TOC 时：隐藏目录或显示「暂无章节」 |
| 兼容 | legacy `chapters[]`：映射为 TOC 或沿用旧分段 UI，不挡阅读 |
| i18n | 目录、第 N 章、暂无章节 |
| 单测 | TOC 归一化、跳转下标计算 |

**验收**：阅读页可打开目录并跳到章节起点。
