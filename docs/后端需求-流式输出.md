# 后端需求：局内 AI 真流式输出

## 背景

前端已接好 SSE 流式客户端（`Romance/src/lib/platformPlayAi.ts` → `streamPlayViaPlatform`）。
目前平台只有同步接口 `/api/romance/play/complete`，生成完才一次性返回，玩家看到的是整段跳出来。
新增下面这个流式接口后，局内剧情演绎、日记本周记等所有 `streamChat` 调用会自动变成逐字输出，前端无需再改。

接口未上线（返回 404 / 405 / 501，或响应不是 `text/event-stream`）时，前端会自动退回 `/complete`，不会出错。

## 接口

`POST /api/romance/play/stream`

请求头：

- `Authorization: Bearer <JWT>`（与 `/complete` 相同）
- `Accept: text/event-stream`
- `Content-Type: application/json`

请求体：与 `/complete` 完全相同，多一个 `"stream": true`。

```json
{
  "messages": [{ "role": "system", "content": "…" }, { "role": "user", "content": "…" }],
  "max_tokens": 4000,
  "stream": true,
  "...aiRouteBody / aiTraceBody 字段": "与 /complete 一致（routeId、feature 等）"
}
```

## 响应

`Content-Type: text/event-stream; charset=utf-8`，建议同时带 `Cache-Control: no-cache`、`X-Accel-Buffering: no`（Nginx 反代必须关闭缓冲，否则会攒成一整段才下发）。

每个事件一行 `data: <JSON>`，事件之间空一行：

| 事件 | 格式 | 说明 |
|---|---|---|
| 正文片段 | `data: {"delta":"一段文字"}` | 上游每吐出一段就立即转发 |
| 结束 | `data: {"done":true,"pointsDeducted":3,"remainingPoints":97}` | 扣点在流结束时按实际用量结算，字段含义同 `/complete` |
| 出错 | `data: {"error":"积分不足","code":"INSUFFICIENT_POINTS"}` | 发出后关闭连接；`code` 与 `/complete` 的错误码保持一致 |

也兼容直接透传 OpenAI 风格：`data: {"choices":[{"delta":{"content":"…"}}]}` 与 `data: [DONE]`。
可以发 `: keep-alive` 注释行保活，前端会忽略。

鉴权失败、积分不足等在开始输出前就能判断的错误，可以直接返回非 200 + JSON（同 `/complete`），前端会按原来的方式提示。

## 计费与超时

- 计费、积分账本、溯源字段（`feature`、`routeId` 等）与 `/complete` 相同，按流结束时的实际 token 用量结算。
- 客户端中途断开（玩家关闭页面）时，按已生成的 token 结算，并停止向上游继续拉流。
- 前端看门狗：首包或流中静默超过 120 秒会主动中止，后端无需额外处理。

## 自测

```bash
curl -N -X POST "$API/api/romance/play/stream" \
  -H "Authorization: Bearer $TOKEN" -H "Accept: text/event-stream" -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"写三句话"}],"stream":true}'
```

应看到 `data: {"delta":…}` 一行行陆续出现，而不是最后一次性出现。
