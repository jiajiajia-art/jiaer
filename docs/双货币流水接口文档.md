# 双货币流水接口文档

> 更新时间：2026-06-16

## 一、接口变更概述

### 1.1 合并流水接口

将原有的**积分流水接口**和**钻石流水接口**合并为统一入口，通过 `currency` 参数区分。

### 1.2 新增接口

| 接口 | 方法 | 说明 |
|-----|------|------|
| `/api/auth/currency/exchange` | POST | 钻石兑换积分（10钻石=100积分） |

---

## 二、核心接口

### 2.1 统一流水查询接口

**接口地址**：`GET /api/auth/user/points/activities`

**认证要求**：需要登录

**请求参数**：

| 参数 | 类型 | 默认值 | 说明 |
|-----|------|-------|------|
| currency | string | `all` | 查询类型：`points`=积分流水，`diamonds`=钻石流水，`all`=全部流水 |
| direction | string | `all` | 流水方向：`all`=全部，`income`=收入，`expense`=支出 |
| year | number | - | 筛选年份（如：2026） |
| month | number | - | 筛选月份（1-12） |
| page | number | 1 | 页码 |
| pageSize | number | 20 | 每页数量（最大100） |

**请求示例**：

```bash
# 查询全部流水（默认）
GET /api/auth/user/points/activities

# 只查询积分流水
GET /api/auth/user/points/activities?currency=points

# 只查询钻石流水
GET /api/auth/user/points/activities?currency=diamonds

# 查询2026年6月的支出流水
GET /api/auth/user/points/activities?year=2026&month=6&direction=expense
```

**响应结构**：

```json
{
  "success": true,
  "data": {
    "points": 100,
    "diamonds": 50,
    "items": [
      {
        "type": "points",
        "activityId": "abc123",
        "activityType": "signin",
        "points": 5,
        "description": "每日签到",
        "createdAt": "2026-06-16T10:00:00Z"
      },
      {
        "type": "diamonds",
        "id": 1,
        "activityId": null,
        "activityType": "diamonds_recharge",
        "amount": 60,
        "description": "钻石充值",
        "createdAt": "2026-06-15T14:30:00Z"
      }
    ],
    "pointsPagination": {
      "page": 1,
      "pageSize": 20,
      "total": 50,
      "totalPages": 3
    },
    "diamondsPagination": {
      "page": 1,
      "pageSize": 20,
      "total": 10,
      "totalPages": 1
    }
  }
}
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
|-----|------|------|
| points | number | 用户当前积分余额 |
| diamonds | number | 用户当前钻石余额 |
| items | array | 流水列表（按时间倒序排列） |
| items[].type | string | 流水类型：`points`=积分，`diamonds`=钻石 |
| items[].activityId | string | 活动ID（积分流水有） |
| items[].activityType | string | 活动类型 |
| items[].points | number | 积分变动（积分流水有） |
| items[].amount | number | 钻石变动（钻石流水有） |
| items[].description | string | 描述 |
| items[].createdAt | string | 创建时间（ISO 8601格式） |
| pointsPagination | object | 积分流水分页信息（currency=all时有） |
| diamondsPagination | object | 钻石流水分页信息（currency=all时有） |

### 2.2 用户信息接口（新增字段）

**接口地址**：`GET /api/auth/user/info`

**认证要求**：需要登录

**变更说明**：新增 `diamonds` 字段，返回用户当前钻石余额。

**响应新增字段**：

```json
{
  "success": true,
  "data": {
    "userId": 12345,
    "nickname": "用户名",
    "points": 100,
    "diamonds": 50,
    "hasSignedIn": false,
    "isMember": false,
    "memberPlan": null,
    ...
  }
}
```

**新增字段说明**：

| 字段 | 类型 | 说明 |
|-----|------|------|
| diamonds | number | 用户当前钻石余额 |

### 2.3 钻石兑换积分接口

**接口地址**：`POST /api/auth/currency/exchange`

**认证要求**：需要登录

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| diamonds | number | 是 | 要兑换的钻石数量（必须为10的倍数） |

**兑换比例**：`10 钻石 = 100 积分`（单向兑换，不可逆）

**请求示例**：

```bash
POST /api/auth/currency/exchange
Content-Type: application/json

{
  "diamonds": 100
}
```

**成功响应**：

```json
{
  "success": true,
  "message": "兑换成功",
  "data": {
    "diamondsSpent": 100,
    "pointsEarned": 1000,
    "remainingDiamonds": 50,
    "remainingPoints": 1100
  }
}
```

**错误响应**：

| 错误情况 | 响应 |
|---------|------|
| 钻石余额不足 | `{"success": false, "message": "钻石余额不足，当前余额：50", "data": {"currentDiamonds": 50}}` |
| 钻石数量不是10的倍数 | `{"success": false, "message": "钻石数量必须为 10 的倍数"}` |

**新增活动类型**：

| activityType | 说明 |
|-------------|------|
| exchange_to_points | 钻石兑换积分（扣减记录） |
| exchange_from_diamonds | 积分兑换收入（积分流水） |

### 2.4 创作者结算接口（改造）

**接口地址**：`POST /api/auth/games/points/settle`

**认证要求**：需要登录（创作者）

**改造说明**：根据游戏的 `share_type` 设置，积分游戏发放积分，钻石游戏发放钻石。同一结算请求可能产生两条结算记录。

**结算逻辑**：

```
查询用户所有游戏
    │
    ├── share_type = 'points' 的游戏
    │       │
    │       └── 计算未结算积分 → 发放积分 → 写 user_point_activities → settlement_records (currency_type='points')
    │
    └── share_type = 'diamonds' 的游戏
            │
            └── 计算未结算积分 → 发放钻石 → 写 user_diamond_activities → settlement_records (currency_type='diamonds')
```

**响应变化**：

```json
{
  "success": true,
  "data": {
    "userId": 12345,
    "pointsSettled": 100,
    "diamondsSettled": 50,
    "pointsFileCount": 3,
    "diamondFileCount": 2,
    "settlementTime": "2026-06-16T10:00:00Z",
    "lastSettlementTime": "2026-06-15T10:00:00Z"
  }
}
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
|-----|------|------|
| userId | number | 用户ID |
| pointsSettled | number | 结算的积分金额 |
| diamondsSettled | number | 结算的钻石金额 |
| pointsFileCount | number | 积分游戏的数量 |
| diamondFileCount | number | 钻石游戏的数量 |
| settlementTime | string | 本次结算时间 |
| lastSettlementTime | string | 上次结算时间 |

## 三、前端使用指南

### 3.1 页面场景对应

| 页面场景 | 推荐接口 | 推荐参数 |
|---------|---------|---------|
| 用户中心"我的资产" | `/api/auth/user/points/activities` | `currency=all` |
| 单独的积分明细页 | `/api/auth/user/points/activities` | `currency=points` |
| 单独的钻石明细页 | `/api/auth/user/points/activities` | `currency=diamonds` |
| 获取用户信息（含钻石余额） | `/api/auth/user/info` | 无需参数 |
| 钻石兑换积分 | `/api/auth/currency/exchange` | POST diamonds |
| 创作者结算 | `/api/auth/games/points/settle` | POST |

### 3.2 注意事项

1. **流水排序**：`currency=all` 时，积分流水和钻石流水会按时间合并排序，最新的在最前面。

2. **分页处理**：
   - `currency=points` 或 `currency=diamonds`：使用 `pointsPagination` 或 `diamondsPagination` 进行分页控制
   - `currency=all`：合并后的列表只取前 `pageSize` 条，如需完整数据请分别请求两种流水

3. **字段兼容性**：
   - 积分流水使用 `points` 字段表示变动
   - 钻石流水使用 `amount` 字段表示变动
   - 前端请根据 `type` 字段区分处理

4. **时区说明**：服务端统一使用 UTC 时间，前端需自行处理时区转换。
