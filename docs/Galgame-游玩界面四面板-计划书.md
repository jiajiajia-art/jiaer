## 4. 分阶段计划（整包顺序）

```text
P1 设置收纳 → P2 四 Tab 壳 → P3 系统静态
    → P4 属性（去白名单 + 每轮自动刷）
    → P5 角色（出场累计）
    → P6 任务目标（quests[]）
    → P7 i18n / 测试 / 打磨
```

### Phase 1 — 图1：功能进设置

- 扩展 `SettingsModal`：积分（只读）、存档、历史、文本、自动；Debug 行按原开关显隐，**只改入口位置、不改处理函数与开关语义**；音乐/音量/重开/退出保留。
- 底栏常规态：**仅四 Tab + 设置**（四 Tab 在 P2 接入；P1 可先只留设置）。
- 从设置进入历史后：底栏切换为「导出视觉小说 / 返回」条（与现历史态一致）。

**验收**：设置内可完成原底栏同等操作；底栏不再出现存档/历史/文本/自动/积分；Debug 行为与迁移前一致。

### Phase 2 — 图2：底栏四 Tab 壳

- `角色 | 属性 | 任务 | 系统` + 设置。
- 统一面板壳；`activePanel` 状态机；空态不挡对白。

**验收**：四面板可开可关，「继续」正常。

### Phase 3 — 图7：系统面板（静态）

- 数据：`morePromptForms`（名称用 description 或条目展示名；**触发关键词**来自 title 拆词；展示 constant / enabled）。
- 纯静态列表，不可进入玩法。

**验收**：与创作后台已配置条目一致。

### Phase 4 — 图5：属性面板

- 去掉 `galgameBetaAttributes` 门槛；入口改底栏「属性」。
- 每轮叙事成功结束后自动触发 SSE；面板打开时展示最近结果；加载/失败态清晰。
- UI 对齐图5 数值卡风格（从面板 JSON 中解析「属性」类数值；解析规则实现时定并补测）。

**验收**：任意 TXT 局可用；推进后数值可见更新（允许一轮延迟）。

### Phase 5 — 图3–4：角色面板

- 资料：世界 NPC；出场：session `encounteredCharacterIds`（对白名 / 场景出场匹配规则实现时写清并单测）。
- 列表 + 详情：**姓名、身份必做**；性格介绍 / 关键记忆有则显、无则藏。
- 读档恢复出场集合。

**验收**：仅见过的角色进列表；读档一致；无性格/记忆时不留空壳区块。

### Phase 6 — 图6 + 顶栏目标

- Session `quests[{ id, title, type, status, description, goalText, tracked, ... }]`。
- AI 每轮或轻量提炼更新；顶栏显示 `tracked` 主线目标。
- 任务面板对齐图6 卡片样式。

**验收**：新目标可生成、状态可更新；读档一致。

### Phase 7 — 质量

- zh/en；纯逻辑单测；移动端布局；历史导出条与四 Tab 不冲突；属性自动刷限频/并发保护。

## 5. 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| 属性每轮全量 SSE | 延迟与费用 | 并发去重、失败不挡主叙事、可后续限频 |
| 角色姓名匹配 | 漏人/重复 | 规则单测 + 文档写清边界 |
| `quests` 注入主叙事 | prompt/协议变更面大 | 独立提炼步骤或 structured 输出字段，与叙事解耦优先 |
| morePromptForms 展示名 | title 是关键词不是「系统名」 | UI：主标题可用 description；副行展示 keywords；缺 description 时用 title 原文 |

## 附录 A. `morePromptForms` 与「系统」面板（已定 A）

系统面板 = 只读列出本局 `world.morePromptForms`：

- **触发关键词**：`title` 按 `,` / `，` 拆词  
- **简介**：优先 `description`（≤15 字侧栏副标题）；可按需摘要 `content`  
- **常驻**：`constant === true` 可标「常驻」
