### 1.1 B-01 具名角色姓名被替换 —— 已查明为前端问题，已修复，后端无需处理

- **根因**：前端读档时的「称谓占名自愈」（`Romance/src/lib/personName.ts`）要求名字首字在中文姓氏表里，「五条悟」被判为不合格，被换成随机名池里的「顾沐晴 / 池晚晴 / 阮清欢」，旧名进了别名，所以身份副标题仍是「五条悟·…」。
- **已修**：真名判定只拦称谓 / 昵称（厨娘、夜班房客、老冯），日文名、西式名放行；读档时按人物 id 对齐作品设定的姓名，已被改坏的存档自动恢复原名。
- 后端无需排查，此条仅作说明。

## 模块二：测试 Bug —— 前端已修复、涉及后端接口的部分

### 2.1 B-07 生成图片无法进素材库

- **现象**：每次生图完成都提示「本地存储空间不足，这张图没能存进素材库」，本轮 10 张图全部未入库，但「使用这张图」正常。
- **根因**：`POST /api/romance/images/generate` 返回的 `data.image` 是 base64 dataURL（1024×1024 约 1–2 MB），本机素材库存在 localStorage（约 5 MB 上限），几张就写满；原逻辑在本机写入失败时**连云端同步也跳过了**。
- **前端已改**（`Romance/src/lib/freeStyle.ts`）：
  1. 本机写满时按最久未用依次清掉「临时 + dataURL」素材后重试，收藏素材和本次新图不清；
  2. 无论本机是否写入成功，都调用 `POST /api/romance/assets` 同步到云端「我的素材」；登录且可同步时不再弹空间不足提示。
- **对后端的影响**：`POST /api/romance/assets` 的调用量会增加，且 `url` 字段可能是很长的 dataURL。

请求示例（沿用现有接口，无新字段）：

```json
POST /api/romance/assets
{ "url": "data:image/png;base64,iVBOR...（或 https://...）", "name": "五条悟", "temp": true, "at": 1795000000000 }
```

- **希望后端**（二选一即可，推荐 1）：
  1. **生图接口直接返回已上传的公网图片 URL**（`data.image` 改为 `https://...`），前端无需改动即可兼容；本机和云端都只存短链接，根治容量问题。
  2. `/api/romance/assets` 接收 dataURL 时服务端转存为文件并返回 URL，同时明确请求体大小上限。

| 待后端确认 | |
|---|---|

### 3.2 剧情记忆系统 · 架构说明（供后端了解，目前全部在前端）

参照「Agent 记忆系统：写入—存储—检索—遗忘」全生命周期实现，代码在 `Romance/src/lib/chronicle.ts`、`Romance/src/lib/memory/retrieval.ts`、`Romance/src/lib/memory/lifecycle.ts`。

| 环节 | 实现 |
|---|---|
| ① 产生 / ② 抽取 | 模型每回合返回的 `memory_updates`（scope=main）作为结构化记忆条目 |
| ③ 决策写入 | ADD / UPDATE / DELETE / NOOP；模型可用 `op` + `replaces` 显式推翻旧记忆，没写时本地按「同一人物 + 变化措辞」判断 |
| ④ 存储 | 存在存档 `state.chronicle[]`；被推翻的旧事实不物理删除，只标记失效（双时态），对应世界书条目停用 |
| ⑤ 混合检索 | 本地向量（字符 1–3 元组 TF-IDF 哈希向量）+ BM25 + 人物 / 地点 / 关键词实体图 1 跳遍历 → RRF 融合 → 按遗忘曲线保持率、重要度、长期标记重排 |
| ⑥ 遗忘与巩固 | 艾宾浩斯衰减（重要度决定稳定度，被召回一次即延长）；重要事件过夜或被召回 2 次晋升长期；过往日常归并为「当日经过」；清理衰减殆尽的琐事和失效超过 30 天的旧版本 |

长中短期上下文：

| 层级 | 内容 | 预算 |
|---|---|---|
| 短期 | 最近剧情原文 + 当前地点陈设 / 在场者穿着 / 在场名单 | 4–10 回合，约 5,000 字 |
| 中期 | 近 2 个游戏日内的事件，按时间全列（相对时间：今天 / 昨天 / N 天前） | 5–10 条，约 900 字 |
| 长期 | 分栏前情摘要（主线进展 / 人物关系 / 承诺与秘密 / 未解悬念）+ 混合检索召回的往事 + 关键事件（经世界书召回） | 摘要 ≤500 字；召回 ≤6 条、约 900 字 |

长期摘要由 `compressMemory` 生成：对话累计约 3,000 token 时，前端异步调用一次 `POST /api/romance/play/complete`（`feature: "chat:complete"`）。

### 3.4 文本向量接口（P2，新接口建议）

后端目前没有 embedding 接口，前端用本地近似向量兜底：能匹配字面相近的说法，但**无法理解近义词**（如「怀表」与「那块旧表」）。如果后端能提供 embedding，前端只需替换向量这一路，检索融合、遗忘、分层逻辑不用改。

建议接口（字段可由后端调整，确定后告知前端）：

```json
POST /api/romance/embeddings
{ "texts": ["沈渔把旧怀表交给主角保管", "那块旧表还在吗"], "aiRouteId": "可选", "feature": "memory:embed" }
```
