# Romance · 创作游戏 / 玩法 Mod / 手机应用需求

改「创作游戏」入口说明，以及**游戏世界表单、玩法包、手机应用**三份数据怎么分开。按第 3 节实现。第 2 节只说明现在哪里有问题，不要照着第 2 节写。

SDK 由平台提供并维护。创作者只在这套 SDK 上创作，不能生成、导出或拥有自己的 SDK。标题和按钮里凡是「并产出专属 SDK」「生成 SDK」「保存并生成 SDK」都删掉或改掉。

创作者交出三样东西，彼此不要混进同一张创作表单：

1. **游戏世界草稿**（Romance 世界表单）
2. **玩法包**
3. **应用草稿**

生成、保存、审核、上架的原有步骤保留。这次先把三分法和入口说明改对。

相关代码：

- 玩法对话：`Romance/src/components/PlayModCreateShell.tsx`、`Romance/src/components/ModWorkshop.tsx`、`Romance/src/lib/kkmodFromCreators.ts`

## 1. 做完后要达到的结果

1. 「创作游戏」三条入口对应三份数据：世界、玩法包、应用。入口文案按 C0。不暗示创作者会得到专属 SDK。
2. 世界表单只描述「这部作品的人、地、设定、主线」。不在生成世界时顺带产出玩法包或应用。
3. 玩法包只扩展玩法，不替换世界的人物、地点骨架和时代。可绑多部世界，可分次安装。世界里只记安装记录。
4. 手机应用只有一套页面 + 积木草稿。世界里不能新建应用，只能安装已上架应用的编号。
5. 世界装上的玩法，预览和开局能真玩到；世界明确没装应用时，开局桌面只有应用商店和设置。
6. 检查 / 审核 / 运行应用，都对着同一套应用草稿字段。

## 3. 要改的内容

### D0. 先分清三份数据（必读）

| | 游戏世界（Romance 表单） | 玩法 Mod | 手机应用 |
| --- | --- | --- | --- |
| 一句话 | 这部作品的世界观和故事底子 | 往世界上叠的玩法扩展包 | 小手机里的 App |
| 创作入口 | 创作游戏 → 游戏世界 | 创作游戏 → 玩法 Mod | 创作游戏 → 手机应用 |
| 创作者交出什么 | 一部世界草稿 | 一份玩法包 | 一份应用草稿 |
| 表单里主要有什么 | 作品名、故事设定、剧本基调、人物、地点、世界书、建角属性、开局、主线/固定事件、结局等**世界本体** | 新地点（带选项/物品）、游戏内页面、往已有玩法格子填的数据 | 名称、简介、图标、截图、页面、积木、要读的游戏数据 |
| 能不能换掉世界的人/地/时代 | 自己就是这份 | **不能**。只追加或覆盖玩法相关条目 | **不能**。不写人物地点 |
| 一部世界怎么用它 | 世界本身 | 用「添加玩法」安装；可装多包、可换版 | 用「手机应用」安装；只存应用编号 |
| 一份能否给多部世界用 | 一部世界一份草稿 | **能**，一包可绑多部世界 | **能**，上架后多部世界都可按编号安装 |
| 预览用什么跑 | 现有游戏运行时 | 同一套游戏运行时（临时挂上包） | 现有手机运行器 |
| 世界表单里留下什么 | 全部世界字段 | 只留安装记录 `playModInstalls`（哪包、哪版、哪天、显隐等） | 只留编号列表 `phoneAppsCfg` |
| 卸载之后 | — | 这包加的地点/事件/页面不再出现；玩家已拿到的物品留着 | 桌面去掉该应用；不删平台上的应用草稿 |

再钉三条边界：

1. **世界本体 ≠ 玩法扩展**  
   人物、地点骨架、世界书、剧本基调、建角属性、世界自己的主线，写在世界表单。  
   通告库、舆情、周报、座驾、头衔、关系玩法、孕育、生活账单等，是**装上对应玩法包之后**才在编辑器里出现的扩展配置，不要当成「没装玩法也该有的世界默认数据」。

2. **玩法里的「页面」≠ 手机应用**  
   玩法包的「一个页面」：游戏大界面里多一屏（例如通告板），读世界已有人物/数值/物品。  
   手机应用：只出现在小手机里，用页面 + 积木描述，由手机运行器打开。  
   不要把手机应用写进玩法包，也不要把游戏内页面做成手机应用。

3. **世界编辑器里的「添加玩法 / 手机应用」是安装面板，不是第二张创作表**  
   创作仍走「创作游戏」三条入口。  
   世界里只勾选已经上架的包或应用，写入安装记录或编号。

### C0. 「创作游戏」弹窗文案

必须用下面原文，不要写「产出专属 SDK」：

- 总说明：选择要创作的类型。游戏世界走现有逻辑。玩法 Mod 和手机应用用对话生成，都运行在平台 SDK 上。
- 游戏世界：填写设定，AI 搭建世界，再进编辑器细调。
- 玩法 Mod：对话生成玩法叠加包。可以是新地点、游戏内页面，或填进已有玩法格子的数据。可绑多个游戏世界，也可分多次安装。用平台 SDK。
- 手机应用：对话生成应用草稿，审核通过后上架，供游戏世界里的手机安装。用平台 SDK。

归属：SDK 属平台；世界草稿、玩法包、应用草稿属创作者。上传写「上传玩法包 / 上传应用草稿」，不要写「生成 SDK / 上传 SDK」。

改：`CreateType.tsx`、`PlayModCreateShell.tsx`、`CreatePlatformApp.tsx` 及同类文案。

### C1. 游戏世界（Romance 表单）

走现有生成世界向导，不新做一套。

1. 填作品名和故事设定，选创作线路，勾选交给 AI 的**世界模块**。
2. AI 按勾选分批生成**世界本体**。
3. 生成完进完整编辑器细调世界表单。

这一步只产出一部游戏世界草稿。

世界生成 / 世界表单**可以写**：

- 作品名、故事设定、剧本基调
- 人物、地点、世界书
- 建角属性、开局日期与资金、货币名
- 世界自己的主线 / 固定事件 / 结局
- 开场与封面等世界展示字段

世界生成 / 世界表单**不要写**：

- 玩法包正文（通告库、舆情包、周报包等整包内容）
- 自动往 `playModInstalls` 里塞推荐玩法
- 应用草稿，或自动往 `phoneAppsCfg` 里塞应用
- 论坛 / 直播 / 咸鱼之类手机应用

世界做好后，再到编辑器里安装**已经上架**的玩法包和应用。

### C2. 玩法 Mod

对话创作。大白话 → 一份玩法叠加包。

包只扩展玩法，**不替换**世界里原来的人物、地点骨架和时代。

一份包可以是下面三种之一，也可以三种都有：

| 形态 | 是什么 | 例子 | 不是什么 |
| --- | --- | --- | --- |
| 新地点 | 地图上多一处可去的地方；有选项；做完可拿到物品 | 旧货铺翻货架还价拿旧钥匙 | 不是改写世界原有主城设定 |
| 游戏内页面 | 游戏大界面多一屏，读世界已有人物/数值/物品 | 通告板页面 | 不是小手机里的 App |
| 内置数据玩法 | 往游戏已有玩法格子填数据：数值、头衔、每周事项、事件、结局等 | 名气数值 + 头衔 + 每周通告 | 不是新建手机应用，也不是另造一套世界 |

安装与绑定：

- 一包可绑多部世界。
- 一部世界可分多次加包；每次只追加本次内容。
- 已开局玩家下次进游戏才看到新内容。
- 物品只在玩家选了对应选项后才拿到，不直接塞背包。
- 改包只替换这包自己的内容；玩家已拿到的物品留着。
- 卸包后：这包加的地点不再出现，这包加的事件不再触发，这包加的游戏内页面不再出现。
- 每部世界各自记安装记录：哪包、哪版、哪天。

预览：现有游戏运行时临时挂上，退出还原；不另做预览引擎。

上架：保存 → 私有测试 → 审核 → 上架 → 各世界「添加玩法」安装。交出的是玩法包，能力来自平台 SDK。

装进某部世界后：

- 世界表单出现该包对应的**扩展配置区**（可改开放项）。
- 完整玩法正文仍属玩法包；世界侧以安装记录为准引用。
- 不要把整包内容复制成「世界本体字段」再丢开安装记录。

### C3. 手机应用（一套草稿）

应用草稿字段只有一套：名称、简介、分类、版本、图标、截图、页面、积木，以及要读哪些游戏数据。

创作入口只有：`创作游戏 → 手机应用`。

步骤：对话生成 → 完整性检查 → 审核 → 上架到应用商店。

世界侧：

- 不能新建应用
- 只能从已上架列表安装
- 只保存应用编号
- 「手机应用」面板 = 安装面板，不是创作表单

运行与预览：现有手机运行器解释同一套页面 / 积木。

审核：是这张应用草稿上的步骤。只审应用本身，不审世界人物、地点、属性、玩法列表。

### P0. 安装时禁止串线

| 在世界编辑器里 | 允许 | 禁止 |
| --- | --- | --- |
| 添加玩法 | 写入 `playModInstalls`；打开对应扩展配置 | 把应用塞进玩法列表；自动预装手机应用 |
| 手机应用 | 写入 `phoneAppsCfg` 编号 | 在世界里新建应用草稿；把玩法包当应用装 |
| 世界本体编辑 | 改人物、地点、世界书等 | 为了「看起来像有玩法」去抄娱乐圈默认通告/舆情进世界本体 |

其它禁止：

- 用娱乐圈默认包自动填创作者没选的玩法
- 另做一套字段不同的「玩家专用应用表单」
- 文案暗示创作者拥有 / 生成专属 SDK

### P1. 世界装上的玩法，预览必须真能玩到

路径：世界里添加玩法 → 出现扩展配置区 → 预览能玩 → 开局同一规则 → 移除后扩展与局内玩法一起消失。

改：

- `registry.ts`：预览 / 开局读世界的玩法安装列表，不要只读世界 `dependencies`。娱乐圈旧存档自动补包，不要作用到创作者世界。
- 玩法包内容装进当前局后要有数据，不能只亮开关。
- `playModCatalog.ts`：短名、配置区、开关只维护一份，且**只含玩法，不含应用**。
- 底栏 / 页内入口：装了才显示。

规则：

- 只改开关、不装包，不算完成。
- 没安装的玩法，预览和开局都不要出现。
- 「显示入口」只控制显隐；移除才关闭玩法。
- 同 id：世界扩展配置里改过的优先；没有的用已装包底稿。
- 事业包装上后，商店允许装「老板直聘」，但不要自动写入世界的应用编号列表。

官方玩法预览（空白世界只加其中一个也必须能玩到）：

| 玩法 | 短名 | 预览里要能做什么 |
| --- | --- | --- |
| 演艺事业包 | `pack-career` | 底栏有事业 / 行业入口；能操作通告或项目 |
| 舆情人设包 | `pack-image` | 底栏有「形象」；能进舆情流程 |
| 娱乐周报包 | `pack-paper` | 能打开周报；报头配置生效 |
| 出行与交通 | `pack-transport` | 换地点时有出行方式与花费 |
| 座驾包 | `pack-cars` | 能买车或换车；依赖出行 |
| 孕育包 | `pack-pregnancy` | 孕育状态可推进或可见提示 |
| 生活开销包 | `pack-living` | 有伙食或周账单；未添加不套娱乐圈默认房租 |
| 头衔包 | `pack-titles` | 有头衔配置与生效；未添加整块不出现 |
| 关系玩法 | `pack-relations` | 人物页有表白 / 婚礼；未添加整块不出现 |

### P2. 上架玩法包可供各世界安装

「添加玩法」= 本地官方玩法 + 已上架玩法包。

上传包写清：名称、说明、版本、作者、依赖、配置区、是否占底栏、默认显示名。

世界记下：包 id、短名、版本、依赖、配置区、是否启用、底栏名、入口显隐、安装日期。

### P3. 应用不要进玩法列表

「添加玩法」和推荐只出现玩法。删掉论坛、视频·直播、咸鱼。装应用只走手机应用安装面板。

### P4. 空的应用编号列表就是没装

| 世界里的值 | 含义 |
| --- | --- |
| 字段不存在 | 旧作品兼容：预装现在 11 个官方应用 |
| 空数组 `[]` | 明确没装：开局只有应用商店和设置 |
| `[{ id }]` | 这些编号开局出现在桌面上 |

不要把空数组收成「字段不存在」。写入只留编号。

### P5. 开局桌面画出本世界已装应用

第一次生成桌面：已装编号 + 应用商店 + 设置。平台新编号也要画。点开后用同一套应用草稿运行。

### P6. 应用审核

对着 C3 同一套应用草稿：

- 只审应用本身
- 先规则、后 AI；不要卡在「审核中」
- 驳回可回到同一张草稿修改
- 通过后上架，供各世界按编号安装

## 4. 验收

- 能向新人讲清：世界是人地设定，玩法包是叠上去的玩法，应用是小手机 App；三份数据创作入口不同，世界里对后两者只做安装。
- 「创作游戏」文案与 C0 一致；无「产出 / 生成专属 SDK」。
- 世界向导跑完：只有世界草稿；`playModInstalls`、`phoneAppsCfg` 不会被自动填上。
- 空白世界未装任何玩法：编辑器不出现通告 / 舆情 / 周报 / 座驾等扩展配置，预览里也没有这些入口。
- 对话做「旧货铺」玩法包：预览能去新地点、做选项；物品选项后才拿到；卸包后地点与事件消失。
- 玩法包的「游戏内页面」出现在游戏大界面，不出现在小手机桌面；手机应用只出现在小手机。
- 同一玩法包装进两部世界；一部世界分两次装两包；安装记录各自独立。
- 空白世界只加事业 / 舆情 / 周报之一，预览能进到 P1 对应步骤。
- 对话做手机应用：检查 → 审核 → 上架后，世界只能按编号安装；世界里不能新建应用。
- 应用编号存成 `[]`，新开一局桌面只有应用商店和设置。
- 「添加玩法」里看不到论坛、直播、咸鱼。
