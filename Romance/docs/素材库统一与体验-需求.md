# Romance · 素材库统一入口与体验优化需求

把分散的**头像库 / 地点库整包 / 地点素材 / 通用配图 / 编辑器本地上传**收成创作者侧同一个「素材库」。  
**创作者可以在素材库里直接上传**（头像、地点整包、地点图、通用图），上传进「我的」云端素材，再选用到当前作品。  
按第 3 节实现。第 2 节只说明现在哪里有问题，不要照着第 2 节写。

适用范围：

- Romance 编辑器内「素材库」统一入口与选用弹窗
- 建角 / 地图 / 封面 / 场景图等所有「选图、选头像、加地点」路径
- 主站仓库素材与 Romance 的数据对齐（同一账号「我的」素材）
- 配套后端上传 / 列表 / 删除 / 引用接口

不包括（除非第 3 节点名）：

- 运营审核工作流大改版（可沿用现有上架；创作者「我的」默认私人可用）
- 玩家局内自己上传头像到平台库（建角仍只从创作者开放的池 + 公共/系统池选）

相关代码（现状定位用，目标是收拢，不表示继续维持多入口）：

- Romance 头像池（本机）：`Romance/src/components/ModAvatarPoolsEditor.tsx`、`Romance/src/game/avatarPools.ts`
- Romance 选头像：`Romance/src/components/AvatarLibraryPicker.tsx`、`Romance/src/lib/platformAvatarLibrary.ts`
- Romance 通用选图 / 上传：`Romance/src/components/ImagePicker.tsx`、`Romance/src/lib/freeStyle.ts`
- Romance 地点整包选用：`Romance/src/components/ModRoomTreeEditor.tsx`、`Romance/src/lib/platformLocationLibrary.ts`
- Romance 地点素材只读：`Romance/src/components/PlatformLocationAssetPicker.tsx`
- 主站私人头像库：`src/page/warehouse/WarehouseAvatarLibrary.tsx`、`src/api/galgame/avatarLibrary.ts`
- 运营公共/系统头像：`src/components/admin/AdminPublicAvatarManager.tsx`
- 运营地点整包：`src/components/admin/AdminLocationLibraryManager.tsx`、`src/api/galgame/locationLibrary.ts`
- 运营地点素材：`src/components/admin/AdminLocationAssetLibraryManager.tsx`、`src/api/galgame/locationAssetLibrary.ts`
- 后端：`Interactive-fiction-backend/interface/routes/avatarLibrary.js`、`locationLibrary.js`、`locationAssetLibrary.js` 及对应 service / store 上传

## 1. 做完后要达到的结果

1. 编辑器里**只有一个「素材库」入口**；头像、地点整包、地点图、通用图都在里面用 Tab 切换。
2. **创作者在每个 Tab 都能上传到「我的」素材**（云端、跟账号走）；同时能浏览并选用「公共 / 系统 / 平台精选」（只读）。
3. 上传按钮醒目、流程完整：选文件 →（必要裁剪/填标签）→ 上传成功 → 立刻出现在「我的」列表 → 可一键「用于当前作品」。
4. 建角选头像、地图加地点、地点换图、作品封面等，全部优先打开**同一套素材库组件**，不再各写一套上传。
5. 「我的」与主站仓库打通：Romance 上传的，仓库看得到；仓库上传的，素材库看得到。
6. 失败可理解：未登录、权限、对象存储 503、格式/尺寸不合规，都有中文提示，禁止空白失败。
7. 公共库仍由运营维护上架；**创作者上传默认进私人「我的」，不自动变公共**，但创作者自己随时能用。
8. **编辑器里 AI 生成的图，采用后一律进入「我的」素材库**（可再选用到别处）；未采用的可暂存，规则统一、有说明。
9. **任意需要图的位置都能「从素材库选择」**：能看到自己上传的、生图收下的、公共的；禁止某些入口点「素材库」却换成另一套只读空库。

## 2. 现在的问题（不要照着实现）

| 环节 | 现在发生的事 | 问题 |
| --- | --- | --- |
| 入口分散 | 头像池、仓库头像库、地点库、地点素材、ImagePicker 本地传各一摊 | 不知道在哪传、传了给谁用 |
| 头像池 | Romance「我的头像池」只写 localStorage，且**故意不进**通用素材库 | 换设备没了；生图/上传头像与「素材库」列表对不上 |
| 创作者上传地点 | 「从地点库添加」「地点素材库」多为只读；真上传在运营后台 | 创作者侧像坏了或「不能传」 |
| 上传 ≠ 生效 | 头像要再勾玩家可选；地点封面 upload 后还要保存条目；未上架列表没有 | 传了却选不到 |
| **生图有的进库有的不进** | `ImagePicker` 采用生图会 `rememberImageAsset`；`AiImageGen` 生成时进**临时**库（7 天）；头像池上传**不进**通用库；部分封面/其它入口生图路径不一致；地点位若带 `platformAssetPurpose`，点「素材库」打开的是**平台地点素材库**，看不到本机生图 | 创作者觉得「同一套生图，有的进素材库有的不行」 |
| **不能从素材库选图来用** | 通用位可从本机 `star:assets` 选；地点场景/大地图点「素材库」只读平台库且**创作者不能往里传**；头像位走头像池/平台头像，又不读通用素材库 | 「素材库里明明有图，这个位置选不到 / 不能当上传源」 |
| 私人 ≠ 系统 | 私人头像不会进系统库 | 和预期「素材库里都能用」不一致（应用层要讲清范围） |
| UI | 默认折叠、浅灰虚线「＋」、原生 file | 上传入口看不清 |
| 登录 / 存储 | 嵌 Romance 丢 token；存储未注入 503 | 空列表被当成功能损坏 |

### 2.1 生图与「选不了素材库」——现状机制说明（给产品对齐，实现按第 3 节改掉）

当前至少三套「库」名字都叫素材/头像/地点，但数据不通：

1. **编辑器通用素材库**（`freeStyle` / `star:assets`，多在本机）  
   - 本地「上传」、部分「采用生图」会进来。  
   - AI 刚生成未点收藏：常是 **temp，7 天没用就清**。  
2. **头像池 / 平台头像库**  
   - 头像上传注释写明：**不顺带收进通用素材库**。  
3. **平台地点素材库**（运营上架；`PlatformLocationAssetPicker`）  
   - 地点大地图/场景图点「素材库」时走这里，**只读、与通用库列表不是同一份**。

因此会出现：

- A 处生图进了通用库，B 处（地点）点「素材库」却看不到；  
- 头像生图/上传只在头像池，通用库没有；  
- 想「从素材库挑一张当作这里的上传」——有的控件根本没接选用，或接的是另一套只读库。

## 3. 要改的内容

### D0. 产品原则（必读）

1. **一个入口：素材库。** 创作者上传、浏览、删除「我的」、选用到作品，都在这里完成。  
2. **创作者可以上传。** 头像、地点整包、地点图、通用图，均支持创作者上传到「我的」。  
3. **两层归属：**  
   - **我的**：当前登录创作者私有，云端持久化，本账号任意作品可引用。  
   - **公共 / 系统 / 精选**：平台或运营上架，创作者只读选用，不可在创作者端改公共库内容。  
4. **选用进作品 = 写入当前作品草稿**（复制或引用 ID，实现选定一种并全文统一）；保存作品后预览/开局能用到。  
5. **不再把「仅本机 localStorage」当正式方案。** 迁移期内若暂存本机，必须角标「仅本机」，并提供「同步到云端」。

### D1. 信息架构与入口

**入口位置（都要能打开同一面板）：**

- Romance 编辑器顶栏或①基础固定按钮「素材库」
- 建角 / 角色头像选择
- 地图「从地点库添加」
- 地点预览图 / 封面 / ImagePicker「从素材库选择」
- （建议）主站「我的仓库」与编辑器共用同一数据，仓库可作为第二入口，UI 分类与编辑器一致

**素材库面板结构：**

```
素材库
├─ Tab：头像
│   ├─ 筛选：我的 | 公共/系统
│   ├─ 主按钮：上传头像
│   └─ 网格列表（选中 / 用于本剧 / 删除我的）
├─ Tab：地点整包
│   ├─ 筛选：我的 | 平台精选
│   ├─ 主按钮：上传地点整包
│   └─ 卡片列表（预览树摘要 / 添加到当前作品 / 删除我的）
├─ Tab：地点图
│   ├─ 筛选：我的 | 公共
│   ├─ 主按钮：上传地点图
│   └─ 网格（用于当前地点 / 复制 URL 写入字段）
└─ Tab：通用图（封面 · CG · 道具等）
    ├─ 筛选：我的 | 公共
    ├─ 主按钮：上传图片
    └─ 网格
```

每个 Tab 顶部固定一条说明，例如：  
「上传到「我的」后可在任意作品选用；公共素材由平台提供，可选用不可改。」

### D2. 创作者上传：分类细则

#### D2.1 头像

**创作者可上传。**

| 项 | 要求 |
| --- | --- |
| 入口 | 素材库 · 头像 · 「上传头像」主按钮（高对比，禁止只靠浅灰虚线＋） |
| 文件 | 常见图片格式；上传前正方形裁剪（沿用/对齐现有裁剪门闸） |
| 元数据 | 性别、年龄段、背景等标签：按现有头像库必填项收集；缺了不能静默失败，表单标红 |
| 存储 | 走账号云端 `/api/avatar-library`（或等价）；写入当前用户「我的」 |
| 成功后 | 立刻出现在「我的」；提供「加入本剧可选头像」「设为某角色头像」 |
| 建角 | 玩家仍只从「本剧开放池 + 公共/系统」选；创作者上传后若要给玩家用，须一键加入本剧可选（可默认勾选「加入当前作品可选池」） |
| 不自动 | 私人头像不自动变成公共/系统 |

#### D2.2 地点整包

**创作者可上传。**  
整包含义：可加入作品地图的地点数据包（名称、封面、地点树/房间结构、可选默认图等；字段与现网 `location-library` 对齐，缺的补创作者侧 create API）。

| 项 | 要求 |
| --- | --- |
| 入口 | 素材库 · 地点整包 · 「上传地点整包」 |
| 流程 | ① 填名称/简介 ② 上传封面 ③ 编辑或导入地点树（可用现有结构编辑器简化版）④ 保存到「我的」 |
| 关键 | **上传封面 ≠ 完成**；必须点「保存到我的地点库」后列表才有；保存失败要报错 |
| 选用 | 「添加到当前作品」= 复制进当前作品地图（与现「从地点库添加」一致）；提示「请保存作品」 |
| 平台精选 | 运营上架的整包只读；与「我的」分栏 |
| 权限 | 创作者对自己的整包可删/改；不可改他人或精选 |

#### D2.3 地点图（单图素材）

**创作者可上传。**

| 项 | 要求 |
| --- | --- |
| 入口 | 素材库 · 地点图 · 「上传地点图」；地点编辑选图也可「上传到我的并选用」 |
| 用途 | 场景背景、地点详情横幅、地图点封面等 |
| 存储 | 云端地点素材库用户侧（扩展现 `location-asset-library` 或并列「我的」接口） |
| 选用 | 写入当前地点对应图片字段；列表马上可再次选用 |
| 与整包关系 | 地点图是单图；整包是结构化地点数据。两者 Tab 分开，文案写清 |

#### D2.4 通用图

**创作者可上传。**

| 项 | 要求 |
| --- | --- |
| 用途 | 作品封面、CG、道具、自定义插图等 |
| 入口 | 素材库 · 通用图；以及原 ImagePicker「从素材库选 / 上传到我的」 |
| 存储 | 统一「我的通用图」云端；逐步替代「只压成 dataURL 塞进稿」的默认路径（大图禁止无提示地塞本地） |

### D3. 选用进作品（统一行为）

1. 在素材库点「用于当前…」或在业务页打开素材库勾选确认。  
2. 写入当前作品草稿对应字段（头像池 / 房间树 / 图片 URL 或资源 ID）。  
3. Toast 或横幅：「已加入当前作品，记得保存」。  
4. 预览 / 开局读取作品草稿，不要求玩家能访问创作者私人库未开放部分。  
5. 删除「我的」素材时：若作品仍引用，提示「作品内已引用的图会保留副本或失效（实现选定一种，UI 说清楚）」——推荐：**加入作品时复制为作品内资源，删库不影响已保存作品**。

### D4. 体验与视觉（必做）

1. 每个 Tab 顶部主按钮文案固定：「上传头像」「上传地点整包」「上传地点图」「上传图片」。  
2. 主按钮样式：实心或高对比描边；浅色/深色主题都清晰；移动端可点区域 ≥ 足够手指点击。  
3. 禁止：默认折叠到看不见才是唯一上传入口；禁止仅原生 `<input type="file">` 无标签。  
4. 列表：缩略图 + 名称 +「我的/公共」角标；加载中/空/错三态齐全。  
5. 空状态：  
   - 我的：「还没有素材，点击上方按钮上传」  
   - 公共：「暂无公共素材」  
   - 未登录：「请先登录后使用云端素材库」  

### D5. 后端与权限

1. **创作者上传「我的」**  
   - 头像：登录用户可 `upload` + `create` 私人条目（已有则打通 Romance 调用）。  
   - 地点整包：新增或开放创作者侧 `create/update/upload`（仅自己的 `ownerId`）；列表支持 `mine` + `public/active`。  
   - 地点图 / 通用图：创作者可上传到自己的素材桶；list 分 mine / public。  
2. **公共/系统/精选**  
   - 仍仅运营可写；创作者 GET 已上架。  
3. **存储**  
   - `putBinary` 不可用时返回明确错误码与中文信息；前端展示。  
4. **鉴权**  
   - Romance 与主站同一套 token；过期引导登录。  
5. **校验**  
   - 类型、大小上限、头像正方形、必填标签；失败返回字段级错误。

### D6. 迁移

1. 现有本机头像池：首次打开素材库时检测 → 「发现本机头像，是否上传到我的云端素材库？」支持一键迁移。  
2. 作品里已有 dataURL / 外链：不强制迁移；新上传默认走云端。  
3. 文档与 UI 停用「头像池（仅本机）」作为主文案。

### D7. AI 生图与素材库（必做，回应「有的进库有的不进」）

1. **统一规则（写进 UI）：**  
   - 点「使用这张图 / 采用」→ **必须**写入当前账号「我的」素材库（云端），并用于当前字段。  
   - 仅生成未采用 → 可进「暂存」并标明天数；或明确「未采用不入库」（二选一，全文统一；推荐：暂存 + 可收藏）。  
   - 点「收藏到素材库」→ 长期保留（去掉临时标记）。  
2. **所有生图入口同一套收库函数**（封面、地点、结局 CG、批量生图、头像位等），禁止有的调 `rememberImageAsset`、有的只写字段、有的进头像池却不进「我的」。  
3. **头像：** 生图/上传进入「我的 · 头像」；若同时需要出现在通用图，可提供「同时放入通用图」开关，默认开或按产品定，但**列表里要能找回来**。  
4. **文案：** 采用成功 Toast：「已用于此处，并已保存到我的素材库」。

### D8. 从素材库选择 / 当作上传源（必做，回应「不能选素材库的图」）

1. 凡带图片的字段（封面、地点图、CG、美化贴图、头像等）必须提供：**上传本地 | 从素材库选择 | （可选）生图**。  
2. 「从素材库选择」打开**统一素材库面板**，默认停在对应 Tab，且能看到：  
   - 我的（含本次生图已采用/已收藏）  
   - 公共/精选（只读）  
3. **禁止**：地点字段点「素材库」却只打开运营只读库、看不到「我的」生图。平台精选可作为子筛选，不能顶替「我的」。  
4. **选用 = 用于当前字段**（等同上传成功后的写入）；不要求再「上传一次」。若技术上需转存作品副本，后台做，用户无感。  
5. 允许在素材库内：选中我的图 →「用于当前作品的 xxx」；也允许把本地文件「上传到我的」后再选。  
6. 空库时引导：「去生成或上传；生成后点采用会自动进库」。

### D9. 本期不做

1. 创作者一键把私人素材发布为全站公共（可二期：提交审核）。  
2. 玩家在局内上传图片到平台素材库。  
3. 重做运营审核后台信息架构（创作者侧命名对齐即可）。

## 4. 交互流程（验收用）

### 4.1 上传头像并给玩家用

1. 打开素材库 → 头像 → 上传头像 → 裁剪 → 填标签 → 成功  
2. 勾选「加入当前作品可选池」（可默认勾选）  
3. 保存作品 → 预览建角 → 能选到该头像  

### 4.2 上传地点整包并加入地图

1. 素材库 → 地点整包 → 上传地点整包 → 填信息 + 封面 + 地点树 → 保存到我的  
2. 「添加到当前作品」→ 地图出现对应地点  
3. 保存作品 → 预览可前往  

### 4.3 上传地点图并挂到地点

1. 素材库 → 地点图 → 上传  
2. 在地点编辑点「从素材库选择」→ 选中 → 预览图更新  

### 4.4 只选用公共素材

1. 切换到「公共/精选」→ 选中 → 用于作品  
2. 无上传按钮或上传按钮不可用并注明「公共区由平台维护」

### 4.5 生图进库再选用到别处

1. 在地点 A 点「生图」→ 生成 →「使用这张图」  
2. 打开素材库 · 地点图/通用图 →「我的」里能看到这张  
3. 到封面或另一地点点「从素材库选择」→ 能选中同一张并写入  

### 4.6 从素材库选图（不再「选不了」）

1. 任意图片位点「从素材库选择」  
2. 能看到我的（含生图采用）+ 公共
