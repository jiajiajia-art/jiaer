# Romance · 局内游玩页体验需求

按第 3 节实现。第 2 节只说明现在哪里有问题，不要照着第 2 节写。

适用范围：Romance **局内游玩页**（含作者预览）、**建角 / 自设开局页**（同属预览与开局路径）。
不包括：世界编辑器本体、生成世界向导、手机应用内页。
不改：主线完成条件公式、存档主结构、结算 / 路费公式。

附：产品标注截图。红框处对照验收。

相关代码（落点可调，验收不变）：

- `GameShell.tsx`：顶栏、☰ 菜单、游戏设置（暗色开关）
- `HomeTab.tsx`：场景、人物名标、提示回复（剧情选项）
- `StoryTab.tsx`：旁白、气泡、心事
- `MudChrome.tsx`：底栏
- `StoryQuestPanel.tsx`：剧情志（主线 / 羁绊 / 支线 / 回顾）
- `GameContext.tsx`：换地点抵达文案
- `index.css`：暗色变量、叙事字色、阅读卡 / 旁白底

## 1. 做完后要达到的结果

（1）顶栏「当前主线」和局势提示合成一块，信息都还在。
（2）暗色下叙事、底栏、人物名标都可读；浅色不回退。
（3）旁白、对话、心事、玩家行动条跟「设置 · 游戏字体」同一套字。
（4）☰ 菜单不再有「编辑器」；创作仍走完整编辑器 / 预览「返回编辑器」。
（5）进入新地点后，叙事区有该地点剧情描写，不只剩「你来到××」系统句。
（6）有事件可跟进时，提示回复里至少一条标色，和普通选项分得清。
（7）游戏设置里暗色模式点一次即开关。
（8）剧情志「主线」跟当前作品主线，不再写死「星途」和名气 / 口碑 / 作品。
（9）剧情志去掉「羁绊」页签；人物关系仍可从人脉 / 人物页查看。
（10）局内状态顶栏（头像 / 周次日期 / 行动点金钱 / 当前主线）**只在「世界」Tab 显示**；人脉、手机、设置等其它底栏页都不显示这条顶栏。
（11）无剧情选项时的「行动灵感」必须跟当前作品 / 当前地点，禁止再塞娱乐圈死文案（如「给经纪人林宜打个电话」）。
（12）地点详情弹窗与场景实景用 **同一套地点图**；地点有图时弹窗必须显示，不能只剩渐变占位。
（13）内容卡里地点说明与下方剧情段：不要莫名首行缩进，字体规格与正文一致；地点说明文案必须是本地点，不能写成「你来到了「新地点」」。
（14）剧情解析出的**新人物**必须落成可点的人物条目（有名片 / 档案入口），并尽量配上头像；不能「正文里出现了，花名册 / 人脉侧像没这人」。
（15）剧情解析出的**新地点**必须落成地图可去条目（自建点），并尽量从**地点素材库**按名称 / 标签相似度配上场景图；不能只改 `world.location` 字符串、地图上却没有点、也没有图。
（16）结局评定页：视觉跟随设置里的皮肤 / 主题（含深浅）；整页可下滑看完后记与按钮；纪念照有可用图时必须显示，不能长期空拍立得。
（17）建角「人设」页：基本信息与属性不要中间空一截像缺块；属性骰子点了要有可见变化，或没有可掷项时干脆不显示死按钮。

## 2. 现在的问题（不要照着实现）

问题一：顶栏主线条和局势飘条叠两层，挤叙事区。
问题二：暗色下叙事字、底栏字、人物名标对比不够，看不清。
问题三：叙事区字体不统一（旁白一套、心事一套、行动条又像第三套）。
问题四：局内菜单挂了「编辑器」，玩家不该碰，创作者也不需要这第二入口。
问题五：换地点常只有系统抵达句，没有新地点剧情感。
问题六：事件触发后，提示回复看不出哪条跟事件有关。
问题七：暗色开关要先展开再点一次，共两步。
问题八：剧情志主线写死娱乐圈模板（「星途」、名气三格），和当前作品对不上。
问题九：剧情志「羁绊」页多余，且多依赖娱乐圈情感线死数据，和通用作品不对齐。
问题十：人脉 / 手机 / 设置等非世界页也挂着世界状态顶栏，占空间、和当前页无关。
问题十一：无剧情选项时，行动灵感写死娱乐圈三条（含「给经纪人林宜打个电话」），伪人旅馆等作品也会冒出无关人物。
问题十二：点地点名打开详情时，横幅只读旧舆图 `map.photos`，不读地点自己的背景图 / 地图覆写图；场景页有图，弹窗却是空渐变。
问题十三：内容卡顶部地点说明强制 `text-indent: 2em`，下方剧情段没有，看起来像「空了一块 / 缩进怪怪的」；地点说明还可能残留「你来到了「新地点」」占位文案，和当前「厨房」等真名对不上，观感也像另一种字。
问题十四：新人物解析后常像「没出现」——未点「结识」不进人脉；名片不显眼或未挂上；头像池未命中时只剩首字，档案侧几乎无条目感。
问题十五：AI 写出新地名时，`roomByName` 对不上已有房间就不会建点、也不会移 `sim.room`；地图无条目、无场景图；素材库里明明有相似地点图却不会自动配。
问题十六：结局评定页 CSS 写死「粉白少女感、固定浅色，不随全局皮肤 / 深色」，和设置里换的皮肤主题脱节。
问题十七：作者预览外壳 `overflow-hidden`，结局页自身又未建纵向滚动容器 → 内容被裁切，无法下滑看后记 / 按钮。
问题十八：拍立得纪念照故意排除与主视觉相同的图；本局只有一张可用图时拍立得变空花占位。
问题十九：建角人设页把「基本信息」「属性」拆成两张卡，中间留出一条空白带，看起来像上面缺了一块可点区域。
问题二十：属性标题旁骰子在全部为「固定开局」时仍显示；`rerollAttrs` 重算结果相同，点了像没反应。

## 3. 要改的内容

### 3.1 顶栏：主线 + 局势合并（仅世界页）

把「当前主线」和下面那条局势提示，合成 **一个** 顶栏。本条只作用于 **「世界」Tab**（见 3.10）。

- 主行：主线名 / 当前节点
- 同栏副文案：局势摘要（原飘条内容）
- 需要详情就在这一栏里点开，不要再单独飘第二条

验收：世界页上，同时有主线和局势时顶部只占一块；两条信息都还在；窄屏不把叙事窗顶没。


### 3.2 暗色可读

暗色下局内常读文字，相对真实背景对比要够。

| 区域 | 要求 |
| --- | --- |
| 叙事正文 / 阅读卡 | 禁止近黑字压深色底 |
| 叠图旁白底 | 深底浅字（或等价可读）；透明度仍跟设置 |
| 默认对话气泡 | 底与字对比够；不误伤 plain / outline / comic |
| 底栏未选中文字 | 可辨（如「世界」） |
| 在场人物名标 | 禁止白底浅字糊掉 |
| 各皮肤暗色 | 次要字同步够亮 |

验收：暗色能读完旁白；切回浅色不糊；作者预览与正式开局一致。


### 3.3 叙事字体统一

读故事相关文字，一律跟「设置 · 游戏字体」。

覆盖：旁白、NPC / 玩家气泡、心事、玩家行动条、流式输出中的同等内容。

- 心事不要用会掉成系统黑体的中文斜体
- 行动条可用略粗字重，但不能换字形家族
- 底栏、菜单等界面字不要求跟小说字同一套

验收：切换字体预设后，上述区域一起变；同一屏看不出换了三套字。


### 3.4 删掉局内菜单「编辑器」

从 ☰ → SETTINGS **删除**「编辑器」这一行及其总入口弹层。

验收：正式开局和作者预览都没有这项；「AI 配置」「游戏设置」仍在；「返回编辑器」和完整世界编辑器仍可用。  
注意：是删掉，不是改成「仅预览显示」。


### 3.5 进新地点要有地点剧情

换地点抵达后，故事流里要有该地点的可读描写（氛围 / 陈设 / 在场人或异常），不能只有「你来到××（行动点 -N）」。

- 优先用地点 desc、首次 intro、在场人物、当前主线上下文
- 系统抵达句可保留，但不能单独充当全部反馈
- 短而完整即可，不要求每次超长 AI 章回

验收：A→B 抵达后能读到关于 B 的描写；行动点 / 路费不错。


### 3.6 事件相关提示回复要标色

「提示回复」= 输入框旁展开的剧情选项 / 行动灵感。

有可跟进事件时：列表里至少一条标色（描边 / 底色 / 标签均可），文案对准该事件。  
无事件时：不要乱标色。

验收：有事件时能指出哪条是事件项；点了能正常送出；浅色暗色都可读。


### 3.6.1 行动灵感跟当前作品，禁止娱乐圈死文案

没有 AI / 剧情选项时，展开的「行动灵感」不能再用写死的娱乐圈句子。

现在（错）：`HomeTab` 里常量大致是「环顾四周…」「给经纪人林宜打个电话」「翻开今天的日程本」——任何作品无选项时都会出现，和伪人旅馆等世界观冲突。

要改成：

- 灵感文案根据 **当前世界 + 当前地点 + 在场人物 / 主线** 生成或配置；本作品没有的人物名绝不出现
- 允许用中性通用句（如「环顾四周」「和在场的人说句话」），但不要点名娱乐圈专属角色
- 若作品 / 玩法包提供了灵感列表，优先用那份；没有再用中性兜底，禁止回落到「林宜」等死数据
- 有真正的 `game.options` 时，仍只显示剧情选项（现有逻辑可留），灵感只是无选项时的兜底

验收：伪人旅馆等非娱乐圈作品展开行动灵感时，看不到「经纪人林宜」及同类娱乐圈专名；灵感读起来像在当前地点能做的事。


### 3.7 暗色开关点一次即可

游戏设置里，暗色不要再包进折叠分支。

- 点这一行（或行上开关）立刻开 / 关
- 状态文案与真实状态一致
- 美化、字体等多选项仍可折叠，不在本次改

验收：暗色只需一次点击，没有「先展开再开启」。


### 3.8 剧情志主线跟当前作品

剧情志「主线」页读当前世界主线，禁止娱乐圈死模板。

| 现在（错） | 改成 |
| --- | --- |
| 标题写死「星途 · 第 N 章」 | 当前主线名（或主线 · 节点）；没有章节设定就不要硬造章号 |
| 每 4 周硬算一章 | 按主线节点；没有节点就只显示进行中 / 已完成 |
| 固定名气 / 口碑 / 作品三格 | 本作品相关指标才显示；没有这些概念就不要画 |
| 顶栏有主线，页内却说「尚未配置」 | 与顶栏同一数据源（世界 storylines / homeMainQuest） |

验收：非娱乐圈作品看不到「星途」和无意义三格；有主线时目标与顶栏一致。


### 3.9 删掉剧情志「羁绊」

从剧情志页签中 **删除「羁绊」**（含对应列表页）。

- 页签只留：主线、支线、回顾（三项；布局跟着收）
- 人物情感 / 关系不在剧情志重复做入口；需要时走人脉、人物页等现有入口
- 清掉仅被羁绊页使用的展示代码；底层人物关系数据若别处还在用，不要误删玩法本身

验收：打开剧情志看不到「羁绊」；主线 / 支线 / 回顾仍可用；人脉或人物页仍能看人物。


### 3.10 非「世界」Tab 去掉状态顶栏

局内这条状态顶栏（头像与档案入口、周次 / 日期、行动点、金钱、合并后的当前主线、以及挂在这条上的 ☰）**只在底栏「世界」显示**。

其它底栏页一律不显示这条顶栏，例如：人脉、手机、设置，以及作品配置出来的其它页签（形象、事业等）。

- 切到非世界页：内容区从页面自己的标题 / 内容顶起，上面不再压一层世界状态
- 切回「世界」：顶栏按 3.1 恢复
- 作者预览外层的 Studio 条（重新开局 / 返回编辑器）不是这条局内顶栏，不要误删
- 若 ☰ 菜单只挂在顶栏：非世界页可不提供同一菜单，或只留该页自带的轻量入口；不要为了菜单又把整条状态顶栏加回来

验收：在设置 / 人脉 / 手机等页看不到头像周次金钱主线条；世界页仍有；底栏切换正常。


### 3.11 地点详情弹窗要显示地点图

点地点名打开的详情弹窗（`EntityText` → `LocDetail`），顶部横幅必须与场景实景用同一套取图逻辑。

现在（错）：弹窗只读 `getWorldMap().photos[id]`（旧舆图槽）；创作者世界的图在地点 `bg` / `mapEdits.background` 上，场景页能显示，弹窗却只剩渐变。

要改成（与 `LocationHero` 一致的优先级即可）：

1. 地图覆写背景（`spotBackground` / mapEdits）
2. 地点自身背景（`roomBgOf` / rooms[].bg）
3. 再回落舆图 photos / defaultPhoto
4. 都没有才用渐变占位

验收：厨房等已配图地点，点开详情横幅能看到同一张（或同源）图，不是空渐变。  
附带：弹窗正文若展示地点说明，用本地点真实 desc / 名称，不要出现标题是「厨房」、正文却是「你来到了「新地点」」这种错位（有则一并修）。


### 3.12 地点说明：去掉怪缩进，字体跟正文，文案对上地点

内容卡里第一段地点说明（`descText`）现在有两处观感问题：

1. **缩进**：写了 `[text-indent:2em]`，下方剧情旁白没有，首行空一大块，像坏图或排版错了  
2. **字体 / 文案**：说明段与下方剧情段规格不统一；且常出现「你来到了「新地点」」这种占位句，人已经在「厨房」却还写新地点

要改：

- 去掉地点说明的强制首行缩进（或正文也统一缩进——默认 **两边都不缩进**，更干净）
- 地点说明与剧情旁白共用同一套 `story-prose` / 字号 / 字重 / 游戏字体（与 3.3 一致）
- 说明文案取本地点真实描述；禁止展示「新地点」占位；没有合格 desc 就隐藏这一段，不要用错名兜底句

验收：内容卡第一段不再空出一截缩进；字体与下方旁白一致；在厨房时不会出现「你来到了「新地点」」。

### 3.13 新人物解析后必须有条目 + 尽量有图

现状（错）：

- `npc_changes` 新建档后只进 `game.npcs`；是否进「人脉」要等玩家点「结识」
- 初遇名片若未挂到本回合 / 弹窗路径，玩家体感就是「名字在正文闪过，系统里像没这人」
- 头像依赖头像池；池空或 `avatar_variant` 对不上 → `avatar` 空，只剩首字

要求：

1. **建档必可见**  
   - 首次合法建档（有具体姓名，非占位称呼）→ 本回合必须出初遇名片（主剧情与弹窗行动同一规则）  
   - 名片可点进人物详情（至少：姓名、身份、简介、头像位）  
   - 「结识」仍决定是否进人民脉列表；**未结识 ≠ 无条目**：详情可从名片进，花名册 / 场景人物层也要能看见「未结识」态（问号头或剪影均可，但不能像没解析出来）

2. **头像**  
   - 优先：AI `avatar_variant` 命中本剧头像池  
   - 其次：本剧随机池抽一张  
   - 再其次：平台头像素材库按身份 / 标签关键词相似检索（有库、已登录时）；命中则写入 `avatar`  
   - 仍无图：明确首字 / 剪影占位，并在详情标明「暂无头像」，不要静默成「像没人」

3. **禁止**  
   - 正文已出场、`npc_changes` 已建档，却本回合无名片、无任何可点入口  
   - 占位名（某人 / 男子 / 陌生人等）建档

验收：新角色首次出场 → 当回合能看到名片并打开详情；结识前后人脉列表规则不变；有池或素材库时应尽量有图。

相关落点：`lib/ai.ts`（建档 / `drawAvatar`）、`game/npcIntro.ts`、`NewcomerCards.tsx`、`GameContext.tsx`（`withNewcomers`）。

### 3.14 新地点解析后必须有地图条目 + 素材库相似配图

现状（错）：

- 转场只认已有房间：`roomByName` 失败则不改 `sim.room`、不建 `mapEdits` 自建点  
- `world.location` 可能变成新字符串，地图与场景图却仍是旧点  
- 平台地点素材库（`location-asset-library`，`location_scene`）只在编辑器选图时用，局内解析从不自动匹配

要求：

1. **识别新地点**  
   - 当本回合 `world.location`（或等价转场字段）是正式地名，且精确 / 包含匹配都对不上已有房间与自建点 → 视为**新地点**  
   - 占位词（某处 / 外面 / 这里等）不建点

2. **自动建点**  
   - 写入 `mapEdits` 自建点：`custom: true`，`name` = 正式地名，`desc` 可用 AI 简介或「你来到了「地名」。」合格句（不要长期留「新地点」占位名）  
   - `link` 默认连到转场前房间（或开局房），保证可寻路回去  
   - 同步 runtime 房间表；`sim.room` 移到新 id；`visited` / `discoveredAt` 按首次抵达记  
   - 地图上能看见该点；内容卡 / 详情用该点名与 desc

3. **配图（相似素材）**  
   - 用途：`location_scene`（场景图）；有大地图位需求时可另匹配 `world_map`，v1 先保证场景图  
   - 匹配顺序：  
     a. 名称全等 / 互含  
     b. 标签 / 描述与地名词、本世界题材关键词的相似（可用现有 2-gram 或同等简单分；取 Top-1，分数过低则放弃）  
     c. 本机素材库同名或高相似图（若局内可读）  
   - 命中：写入该点场景图字段（与 3.11 同源，详情弹窗也能显示）  
   - 未命中：允许暂无图，但条目必须存在；不要用错误旧点的图顶替

4. **同日 / 同名**  
   - 同一正式地名只建一次；再次转到该名走已有 id  
   - 不覆盖作者已手改的坐标 / 已有自定义图（仅补空图）

验收：

- 剧情第一次写到地图上没有的「旧货铺」类正式地名 → 地图多一个可点地点，可抵达 / 可返回  
- 素材库有名称或标签相近的场景图时，新点带上该图；详情与实景同源  
- 未登录或库空时：仍有地点条目，只是可无图

相关落点：`GameContext.tsx`（转场 / `roomByName`）、`mapEdits` / `publicMaps.addSpots` 或同等建点、`platformLocationAssetLibrary.ts`、地点取图与 3.11 对齐。

### 3.15 结局评定页：跟皮肤主题、能下滑、纪念照有图

现状（错）：

- `index.css` 明确写死结局页「固定浅色，不随全局皮肤 / 深色模式变化」；粉白翅膀 / 皇冠版式不读 `look.skin` / 配色 / 深浅
- 作者预览：`App` 里 `author-preview-runtime` / `author-preview-stage` 均为 `overflow-hidden`；`Ending` 根节点只 `min-h-dvh overflow-x-hidden`，竖屏 `main` 无 `overflow-y-auto` → 超出视口的后记、评分维度、底栏按钮滑不动
- 拍立得：`photo = photoImgs.find(s !== heroSrc)`；主视觉已占用唯一头像 / CG 时纪念照为空

要求：

1. **皮肤 / 主题跟随设置**  
   - 结局页读取与局内一致的 `look` / 主题（皮肤、主色、字体、深浅）  
   - 换设置里的皮肤主题后，结局页底色、字色、强调色、面板边线跟着变；不要永远锁死粉白一套  
   - 允许保留「评定卡」版式结构（标题徽牌、拍立得、评级章），但色板与字体必须走主题变量，禁止再写「固定不随皮肤变化」  
   - 深色模式下字与底对比可读（与 3.2 同一标准）

2. **整页可纵向滚动**  
   - 结局页在作者预览与正式游玩都能滑到底：后记全文、维度卡、操作按钮均可达  
   - 做法任选其一写死：结局根节点 `h-full min-h-0 overflow-y-auto`；或预览 stage 对 `screen===ending` 放开纵向滚动。禁止内容被父级 `overflow-hidden` 裁死又无内部滚动  
   - 导出 PNG 的离屏 `end-snap` 仍可 `overflow-hidden`（截图用），不影响可玩页滚动

3. **纪念照（拍立得）**  
   - 有任一可用图（结局主视觉 / 插图 / 已解锁 CG / 主角头像）时，拍立得必须显示一张  
   - 允许与主视觉同图（宁可重复，不要空花）；仅当本局完全无图时才用占位  
   - 加载失败按现有换下一张逻辑，全部失败才占位

验收：

- 设置换成非可爱粉皮肤 / 深色后，再进结局页，观感跟主题一致，不是另一套粉白站外页  
- 预览与游玩：手指 / 滚轮能滑过「结局评定」标题以下全部内容  
- 本局有主角头像时，拍立得不会长期空白

相关落点：`Ending.tsx`、`index.css`（`.end-page` 一段）、`App.tsx`（作者预览 overflow）。

### 3.16 建角人设：基本信息与属性合成一块；骰子要有反应

现状（错）：

- `CharacterCreate` 人设步：`stepWho`（基本信息卡）与 `stepAttrs`（属性卡）两张独立 `Card`，中间 `space-y` 空白带 → 截图像「上面缺了一块」
- 属性标题骰子始终渲染；本作品属性若全是固定 `init`（预览文案无「已掷」），`rollCreatorAttrStarts` 每次同值 → **点了没反应**
- 注释里写过「生日星座」，星座只在关弹窗后的摘要出现，表单生日下不展示（若产品要星座，缺口感更强）

要求：

1. **不要无意义拆卡**  
   - 人设页把「基本信息 + 属性」放进**同一张卡**（或同一连续区块、中间无空白带）  
   - 属性仍可用小标题「属性」分区，但禁止两张大卡中间空一截像缺控件  
   - 有「更多设定」自定义字段时，可仍用下一张卡，紧挨、不要大段空带

2. **属性骰子**  
   - 仅当至少一项 `initMode` 为随机（含旧 `dice`）时显示标题骰子  
   - 点击：只重掷随机项；固定项不变；数字预览必须变（或短暂高亮 / toast「已重掷开局值」）  
   - 全部固定：隐藏骰子，不要留点了没反应的图标  
   - 开局写入仍用同一批 `cattrStarts`（与现逻辑一致）

3. **生日旁（可选但推荐）**  
   - 选好月日后，在生日控件下展示推算出的星座名（已有 `zodiacOf`），避免「生日下面像少一截」

验收：

- 人设页生日与属性列表之间没有「缺一块」的空白带  
- 全固定属性：无属性骰子  
- 有随机属性：点骰子后至少一个开局数字变化，或有明确已重掷反馈  
- 作者预览与正式开局同一套建角页

相关落点：`CharacterCreate.tsx`（`stepWho` / `stepAttrs` / `rerollAttrs`）、`creationItems.ts` / `attrInit.ts`。

## 4. 不要做的事

- 不改主线判定公式、存档主结构、结算 / 路费
- 不借机重做整套皮肤或整页设置
- 不删完整世界编辑器
- 不把界面 chrome 强制改成小说字体
- 不把手机应用内页算进本次
- 顶栏合并不是「删掉局势只留主线」
- 进地点剧情不是「每次强制长篇 AI」
- 删羁绊页签不是删光所有人物关系玩法
- 非世界去顶栏不是删底栏，也不是删作者预览 Studio 条
- 行动灵感去娱乐圈死文案不是取消灵感入口本身
- 新人物「必须有条目」不是改成自动全部结识进人民脉
- 新地点自动建点不是改作者世界编辑器里的原地图定稿；只在本局存档 `mapEdits` 叠加
- 素材库相似配图不是每次强制生图；先匹配已有素材，无匹配可空
- 结局页跟皮肤不是拆掉评定卡重做一整套运营活动页
- 结局页可滚动不是改导出 PNG 离屏卡的裁切逻辑
- 建角合卡不是取消属性列表，也不是强行让固定属性变成随机

## 5. 验收清单

顶栏与菜单

- [ ] 世界页：主线 + 局势同时有时，顶部只有一块
- [ ] 世界页：局势信息仍在
- [ ] 非世界页（人脉 / 手机 / 设置等）：无状态顶栏
- [ ] 切回世界页：顶栏回来
- [ ] 菜单无「编辑器」；AI 配置、游戏设置仍在
- [ ] 返回编辑器 / 完整编辑器仍可用

暗色与字体

- [ ] 暗色：叙事、底栏、名标可读
- [ ] 浅色无回归
- [ ] 暗色开关一次点击即切换
- [ ] 旁白 / 气泡 / 心事 / 行动条跟同一游戏字体
- [ ] 切字体预设后上述区域一起变

地点与选项

- [ ] 换地点后有地点剧情描写，不只剩系统句
- [ ] 行动点 / 路费正确
- [ ] 有事件时提示回复有标色项；无事件不乱标色
- [ ] 非娱乐圈作品行动灵感无「经纪人林宜」等死文案；灵感贴合当前地点 / 世界
- [ ] 已配图地点：详情弹窗横幅显示图片，与场景同源，不是空渐变
- [ ] 内容卡地点说明无怪缩进；字体与旁白一致；无「你来到了「新地点」」错文案
- [ ] 新人物建档当回合有名片 / 可开详情；未结识也有未结识态入口；有池或素材库时尽量有头像
- [ ] 新正式地名首次出现：地图有自建点、可移入；能匹配素材库相似场景图则配上，与详情同源

结局评定

- [ ] 结局页皮肤 / 主色 / 深浅跟随设置，不再锁死粉白固定浅色
- [ ] 作者预览与游玩均可下滑看完后记与底部按钮
- [ ] 有可用图时拍立得显示图片，不长期空花占位

建角人设

- [ ] 基本信息与属性同一连续块，中间无「缺一块」空白带
- [ ] 全固定属性不显示死骰子；有随机项时点骰子数字有变化或明确反馈

剧情志

- [ ] 非娱乐圈作品无「星途」
- [ ] 不硬塞名气 / 口碑 / 作品（除非本作品确有）
- [ ] 有主线时与顶栏一致，不假报尚未配置
- [ ] 无「羁绊」页签；主线 / 支线 / 回顾仍在
