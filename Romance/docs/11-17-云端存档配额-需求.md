# Romance · 云端存档配额需求（2025-11-17）

按第 3 节实现。第 2 节只说明现在哪里有问题，不要照着第 2 节写。

适用范围：

- Romance **玩家正式游玩**的存档读写（手动存档 / 自动存档 / 读档 / 删档 / 重命名）
- 存档管理弹窗的配额展示、会员扩容引导、云端同步状态
- 云存档后端接口的配额校验与会员权益读取

不包括（除非第 3 节点名）：

- 会员购买 / 支付流程本身（只读会员状态，接「扩容至 20 位」权益）
- 作者预览测试存档（不上云、不占配额）
- 素材库、CG、音频等其它云存储配额

相关代码 / 文档（落点可调，验收不变）：

- `Romance/src/lib/cloudSaves.ts`：云存档客户端
- `Romance/src/lib/storage.ts`：本机槽位与 `MAX_SLOTS`（现状写死 6）

## 1. 做完后要达到的结果

1. 玩家正式进度以**云端服务器**为准；本机只做缓存，换设备登录后能续玩。
2. 每个**玩家账号**默认 **10 个**云端手动存档位；**会员**扩容为 **20 个**。
3. **自动存档不占用** 10/20 配额（系统另保留 1 个自动槽，单独展示）。
4. 未登录不能当正式云存档使用，界面有明确提示。
5. 超限时禁止新建；允许覆盖已有槽、允许删除腾位；提示清楚，禁止静默失败。
6. 会员过期后：已有存档可读可覆盖；若占用已超过 10，禁止再新建，直到删到 ≤10 或续费。
7. 存档管理页一眼能看出：身份（普通/会员）、已用、上限、空位、同步状态、扩容入口。
8. **后端强制校验**配额；前端只做体验与提示，不能只拦前端。

## 2. 现在的问题（不要照着实现）

| 环节 | 现在发生的事 | 问题 |
| --- | --- | --- |
| 正式落点 | 本机 IndexedDB 为主，云端为可选镜像（未登录 / 未开通则「仅本机」） | 换设备、清缓存会丢正式进度；与「必须上云」不符 |
| 手动位上限 | `MAX_SLOTS = 6`，按作品本机槽位写死 | 不是账号级 10/20，也未接会员扩容 |
| 配额口径 | 对接文档写「每作品最多 6 手动 + 1 自动」 | 与产品「每玩家 10 / 会员 20」不一致 |
| 界面标注 | 「手动存档位 · 共 N 位」，无普通/会员角标，无「已用/上限」 | 玩家不知道有多少位、会员能扩多少 |
| 超限体验 | 后端约定 `SLOT_LIMIT`，前端未按会员动态上限引导开通 | 满了不知道原因，也缺少会员扩容入口 |
| 自动存档 | 与手动位一起管理，但未写清是否占配额 | 容易和 10/20 数字对不上 |

## 3. 要实现的规则（已拍板，勿再留歧义）

### 3.1 配额定案

| 项 | 定案 |
| --- | --- |
| 计费 / 计数单位 | **按玩家账号**共享上限（该账号下所有 Romance 作品的手动云存档合计） |
| 普通用户 | **10** 个云端手动存档位 |
| 会员用户 | **20** 个云端手动存档位 |
| 自动存档 | **不占用** 10/20；系统位，单独展示 |
| 作者预览槽 | 不上云、不占配额（`id` 以 `__author_preview` 开头） |
| 正式存档前提 | 必须登录；未登录不可写入正式云存档 |
| 本机角色 | 缓存 / 加速；冲突时按 `updatedAt` **后写者胜**，以云端同步结果为准 |
| 超限策略 | 禁止**新建**；允许**覆盖**同 `slotId`；允许**删除**后腾位再存 |
| 会员过期 | 不删已有档；`limit` 降回 10；占用 >10 时只读/可覆盖，不可新建 |
| 校验责任 | 后端必须拦；前端根据接口返回的 `used` / `limit` / `isMember` 展示与引导 |

说明：「账号级 10/20」= 玩家在本产品下所有作品的手动云存档加起来共享一个上限，**不是**每个作品各 10/20。

### 3.2 写入行为

1. **新建**：`used < limit` 才允许；否则返回超限错误。
2. **覆盖**：同一 `slotId` 已存在 → 不增加 `used`，允许写入。
3. **删除**：成功后 `used` 减一，可再新建。
4. **自动存档**：`id = "autosave"`（或约定的自动槽），始终可按节流规则覆盖，不计入 `used`。
5. **重命名**：不改变配额占用。

### 3.3 登录与同步

1. 未登录：存档面板明确「请先登录后使用云存档」；不提供「仅本机正式存档」作为产品路径。
2. 已登录：打开存档列表时拉取云端摘要；云端比本机新的槽下载完整 `state` 写回本机。
3. 同步状态需可见：同步中 / 已同步 / 失败可重试。
4. 单槽体积上限仍建议 10MB；超出 `SAVE_TOO_LARGE`，与配额无关。

## 5. 前后端约定

### 5.1 配额字段（列表或专用接口返回）

建议在 `GET /api/romance/saves` 的 `data` 中携带（或另增 `GET /api/romance/saves/quota`）：

```json
{
  "quota": {
    "used": 7,
    "limit": 10,
    "isMember": false,
    "freeLimit": 10,
    "memberLimit": 20
  },
  "items": [ /* 存档摘要，含自动槽与手动槽 */ ]
}
```

| 字段 | 说明 |
| --- | --- |
| `used` | 仅统计**手动**云存档数量（全账号合计，跨 `gameFileId`） |
| `limit` | 当前生效上限（普通 10 / 会员 20） |
| `isMember` | 当前是否会员 |
| `freeLimit` / `memberLimit` | 固定权益数字，供前端展示「开通可到 20」 |

列表仍可按 `gameFileId` 过滤当前作品的槽；**配额计数必须按账号汇总**。

### 5.2 错误码

| HTTP | code | 何时 |
| --- | --- | --- |
| 401 | `NOT_LOGGED_IN` | 未登录写云存档 |
| 409 | `SAVE_SLOT_LIMIT` | 新建时已达当前 `limit`（推荐统一用此码；若沿用旧名 `SLOT_LIMIT`，前后端文档写清等价） |
| 409 | `STALE_SAVE` | `updatedAt` 冲突，不覆盖云端更新版本 |
| 413 | `SAVE_TOO_LARGE` | 单槽超过体积上限 |

`SAVE_SLOT_LIMIT` 的 `message` 须可直接展示；`data` 建议附带 `{ used, limit, isMember }`。

### 5.3 前端改造要点

1. `storage.ts`：去掉写死 `MAX_SLOTS = 6`；手动位上限改为读接口 `quota.limit`（10/20）。
2. `GameShell.tsx` 存档弹窗：按第 4 节改标题、分区、角标、满额弹窗与会员入口。
3. `cloudSaves.ts`：解析 `quota`；超限错误映射到上述中文提示。
4. 同步更新 `后端对接-字段与接口清单.md` 第 2 节：删除「每作品最多 6 手动槽」表述，改为本需求口径。

### 5.4 后端改造要点

1. 按 `userId` 统计手动槽数量（排除 `autosave`、排除 `__author_preview*`）。
2. 读取账号会员状态，决定 `limit`。
3. PUT 新建时校验 `used < limit`；覆盖同 id 不校验「再占一位」。
4. 会员过期不删档，只降 `limit`。
5. 接口未上线前的 404/405/501「视为未开通」仅为过渡；本需求验收时正式环境必须开通。

## 6. 验收清单

### 6.1 配额与会员

- [ ] 普通用户最多新建 10 个手动云存档；第 11 个被拦，并出现会员扩容说明
- [ ] 会员最多 20 个；角标与「已用 X / 20」正确
- [ ] 自动存档始终可写，且不增加 `used`
- [ ] 覆盖已有槽不增加 `used`；删除后 `used` 减少并可再存
- [ ] 会员过期后：占用 >10 的旧档仍可读取/覆盖，但不能再新建
- [ ] 多作品合计占用共享同一 10/20（验证：作品 A 存 6 个 + 作品 B 存 4 个后，普通用户无法再新建）

### 6.2 云端与登录

- [ ] 未登录：无法正式云存档，提示清晰
- [ ] 登录后写入云端；换设备 / 换浏览器登录后能拉到同一套存档并续玩
- [ ] 打开存档列表能同步云端较新进度；状态文案正确

### 6.3 界面标注

- [ ] 一眼能看出：身份、已用、上限、空位、同步状态
- [ ] 非会员接近满 / 已满有扩容提示与入口
- [ ] 满额点击有说明，无静默失败
- [ ] 不再展示「共 6 位」等旧文案作为正式上限

### 6.4 后端强校验

- [ ] 绕过前端直接 PUT 新建超限 → 返回 `SAVE_SLOT_LIMIT`（或文档约定的等价码）
- [ ] 错误 `message` 为可展示中文，并带上当前 `used` / `limit`（建议）
