# 1119 需求对齐字段

## 背景

建角属性（`AttrDef`）不再支持图标：编辑器去掉了图标输入框，游戏界面也不再显示属性图标。只有**货币属性**保留图标，用于钱包和微信页面的显示。

## 一、属性定义 `AttrDef`（世界书 / 模组 / 存档中的 `attrDefs[]`）

| 字段 | 类型 | 变更 | 说明 |
| --- | --- | --- | --- |
| `icon` | `string?`（最多 2 个字符，emoji） | 收窄用途 | 只有货币属性（被钱包绑定的属性）读写这个字段。普通属性不再写入，前端也不再展示。 |

后端处理建议：
- 保存普通属性时，可以忽略或清空 `icon`；货币属性必须原样保留。
- 旧数据里普通属性的 `icon` 不需要迁移，前端会忽略它。
- 不要把 `icon` 设为必填，也不要做非空校验。

## 二、AI 生成建角属性（世界生成接口返回的属性列表）

| 字段 | 变更 | 说明 |
| --- | --- | --- |
| `icon` | 不再读取 | 返回结果里即使带有 `icon`，前端也会丢弃。如果提示词或响应结构里要求输出 `icon`，可以删掉。 |

## 三、AI 剧情推进 `player_changes.attrs[]`

| 字段 | 变更 | 说明 |
| --- | --- | --- |
| `icon` | 不再读取 | 新建玩家属性时不再带图标。如果响应结构里有这个字段，可以去掉。 |

## 四、顶栏主属性 `TopbarHeroAttr`（`topbar.heroAttrs[]`）

| 字段 | 变更 | 说明 |
| --- | --- | --- |
| `icon` | 已删除 | 前端类型中已移除。剩余字段：`id`、`label`、`text`、`color`。如果后端有存储或下发这个字段，请一并删掉。 |

## 五、玩家属性 `player.attrs[]`

| 字段 | 变更 | 说明 |
| --- | --- | --- |
| `icon` | 保留，仅兼容 | 开局时仍会从属性定义里复制 `icon`（主要给货币用），普通属性不展示。不需要改动。 |

## 不受影响（同名字段但属于其他功能，请勿改动）

- 出行方式 `modes[].icon`、地图点位 `icon`、闲鱼商品 `icon`、模组封面 `icon`、小程序 `meta.icon`、结局评分维度 `icon`

# 第二部分：剧情回合解析、场景记忆、重新生成与回溯

## 背景

本轮前端改动：

1. 状态块（AI 回复里的 ```json 块）解析放宽容错：能修复中文正文里未转义的英文双引号、字符串内直接换行、结构位置误用全角 `，：`、正文里出现 `{}` 或 ```。被截断的块仍然判失败，不会半套结算。
2. AI 在一回合内转场时，本回合的场景记忆、剧情事件改记到**目的地**（以前错记到出发地）。
3. 长期记忆压缩同一时间只跑一个；读档或回溯后返回的过期摘要会被丢弃。
4. 新增「换一版」（重新生成最新回合）和「回溯到这里」（整局退回某回合）。

**前端不需要新接口。** 下面列出的是后端需要保证的透传、存储和计费口径，以及几项可选增强。标「建议」的为可选；标「待前端接入」的表示前端目前还没发送或读取，后端可以先支持。

## 六、剧情演绎接口返回正文（`POST /api/romance/play/complete`、`POST /api/romance/play/stream`）

前端从返回的原始文本里自己拆出「剧情正文 + ```json 状态块」，所以**后端必须原样透传模型输出**。

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 正文文本 | 原样透传 | 不要剥掉 ```json 代码块，不要 trim 中间内容，不要把英文引号或全角标点替换成别的字符，不要过滤 `{}`。 |
| SSE `delta` | 保留换行 | `data: {"delta":"…"}` 里的 `\n` 必须保留，前端按换行区分旁白和台词行。 |
| SSE 结束 | 保持现有协议 | `data: {"done":true,"pointsDeducted":n,"remainingPoints":n}`；出错 `data: {"error":"…","code":"…"}`；也兼容 OpenAI 风格和 `[DONE]`。 |
| `finishReason`（done 事件 / complete 响应） | 建议新增，待前端接入 | 模型因长度截断时返回 `"length"`。前端以后可据此直接提示「输出被截断」，不必再请求补全状态块。 |

状态块中前端读取的字段（由模型输出，后端只透传，列出供提示词或审计对齐）：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `narrative` / `narration` | `string` | 剧情正文（正文为空时兜底）。 |
| `state_diff` | `{ world?, player_changes?, npc_changes?, intimate?, game_end? }` | 与顶层同名字段等价，二选一。 |
| `world.location` | `string` | 地点变化即视为转场；对不上已有地点时前端自动建点。 |
| `world.time` / `world.weather` | `string` | 游戏内时间、天气。 |
| `options` | `{ label, value }[]` | 剧情选项，前端最多取 3 条。 |
| `player_changes` | `{ attrs?: {key,delta}[], identity?, history_add? }` | 也兼容 `player_changes.money: -200` 这类直接写数值的写法。 |
| `npc_changes` | `object[]` | 人物变动和新人物。 |
| `memory_updates` | `{ scope, text, imp?, who?, keys?, op?, replaces?, npc? }[]` | `scope=main` 进剧情事件线，`scope=npc` 进该人物私有记忆。 |
| `scene_memory` | `{ facts?: string[], looks?: {name,outfit}[] }` | 地点陈设或状态变化、人物穿着。 |
| `save_summary` | `string` | 存档摘要，前端截到 60 字。 |
| `thoughts` | `{ name, text, diary? }[]` | 在场人物心事和日记。 |
| `need_clarification` | `string[]` | 需要玩家补充的信息。 |
| `tabs` | `Record<string,string>` | 各页摘要。 |
| `game_end` / `epilogue` | `boolean` / `string` | 结局判定和后记。 |

## 七、演绎请求参数 `max_tokens`

| 字段 | 当前值 | 要求 |
| --- | --- | --- |
| `max_tokens` | 前端默认发送 `4000` | 后端**不要压到比请求值更低**。剧情模式正文约 800~1200 字，再加上完整状态块，4000 偏紧；截断后会报「状态块写到一半时中断」。建议后端放开到至少 `6000`（前端后续可调高请求值）。 |

## 八、状态块补全请求（二次调用）

状态块解析失败时，前端会**再调用一次** `POST /api/romance/play/complete`（超时 40 秒），只让模型补一个 ```json 块：

- `messages` = 本回合原始 messages + `{role:"assistant", content: 已生成正文（最多 6000 字）}` + `{role:"user", content: 补全指令}`
- 每个回合最多补全 1 次。

| 项 | 要求 |
| --- | --- |
| 计费 | 当前按普通请求计费。建议补全请求按较低档计费或免费，因为这是模型自身格式错误导致的。 |
| 标识字段 `feature` | 建议，待前端接入：前端可在请求体里带 `feature: "romance.stateRepair"`，便于后端识别、统计和单独计价。 |

## 九、存档 `GameState` 中的记忆字段（云存档 `/api/romance/saves`）

云存档请整体存储前端提交的 `GameState`，**不要丢弃未知字段，也不要重排数组**。以下字段和本轮记忆修复直接相关：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `memory` | `string` | 压缩后的长期记忆摘要（约 500 字，分栏）。 |
| `memAt` | `number` | 上次压缩时的 `turnCount`。 |
| `turnCount` | `number` | 回合数。**回溯后会变小**，见第十节。 |
| `chronicle[]` | `ChronicleEvent[]`，最多 300 条 | 剧情事件线。字段：`id`、`day`、`time?`、`room?`（地点 id，本轮修复后转场回合记为目的地）、`who: string[]`、`text`、`imp: 1\|2\|3`、`keys?`，以及生命周期字段 `tier?`、`recalls?`、`lastRecall?`、`invalidAt?`、`supersededBy?`、`kind?`。 |
| `sceneMem` | `Record<地点id, { facts: string[]; turn: number }>`，每地点最多 8 条 | 各地点陈设和状态记忆。本轮修复后转场回合写入目的地 key。 |
| `looks` | `Record<人物id, string>` | 人物当前穿着。 |
| `story[]` | `Turn[]` | 剧情流。每条字段：`id`、`role`、`room?`、`scene?`（转场目的地名）、`segments`、`raw?`（AI 原始输出，含状态块）、`thoughts?`、`error?`、`ts`。未开启「保留完整历史」时，压缩后只保留最近 16 条。 |
| `saveSummary` | `string` | 存档摘要（≤60 字），可用作存档列表副标题。 |
| `sim.flags` | `Record<string, number>` | 主线和支线进度：`quest:*` 为主线，`side:<id>`（2 进行中 / 1 完成 / 0 可重复回到未出现 / -1 失败）、`sideDone:<id>`（完成次数）、`sideAt:<id>`（出现的游戏日）为支线。后端只存不改。 |

后端处理建议：
- `story[].raw` 体积较大。如果需要控制存档大小，可以在存储层压缩，但**不要删除这个字段**（排查解析问题要用）。
- 旧存档没有 `chronicle`、`sceneMem`、`looks` 时，前端按空处理，不需要迁移。

## 十、重新生成（换一版）与回溯

纯前端功能，**不新增接口**：快照只保存在本次会话内存里，最多 30 回合，刷新或读档后清空。

| 项 | 对后端的要求 |
| --- | --- |
| 计费 | 每次「换一版」都是一次新的完整演绎请求，按正常演绎计费。如果产品希望重新生成打折或免费，需要后端提供口径；前端可带 `feature: "romance.reroll"`（待前端接入）。 |
| 存档单调性 | 回溯后再存档时，`turnCount`、`story` 长度、`sim.day` 都可能**比云端旧版本小**。后端**不要**按这些字段做「只增不减」校验，也不要拒绝或合并；以前端提交的整份状态覆盖。`updatedAt` 仍会取当前时间，可以继续用它判断新旧。 |
| 冲突判断 | 如果后端用 `turnCount` 判断「云端比本地新」并提示冲突，需改为用 `updatedAt`；否则回溯后每次存档都会误报冲突。 |
| 持久化回溯（可选，未排期） | 如果要支持刷新后仍可回溯，需要新增按回合存快照的接口，例如 `PUT/GET /api/romance/saves/{slotId}/turns/{turnId}`，每局保留最近 N 条，计入或不计入存档配额待定。前端目前未实现。 |

## 不受影响

- 主线完成条件公式、支线判定、结算和路费公式：本轮没有改动，后端无需调整。
- 时间线检查点（`timeline` 和本地检查点，每局 40 个）：仍只存在本地 IndexedDB，与云存档无关。
